## 接入现有工程

使用 Windows x64 Release。编译时将 SDK 目录加入头文件搜索路径，包含 `GrayDetectionV2.hpp`，链接 `GrayDetectionV2.lib`。运行时将 `GrayDetectionV2.dll` 放到测试程序 EXE 同目录，并确保该进程可加载 OpenCV 4.4.0 的 [opencv_world440.dll](../../../third_party/opencv440/bin/opencv_world440.dll) 和 x64 Visual C++ 运行库。C++ 包装类使用 OpenCV 4.4.0 的头文件，C 接口直接接收 GRAY8 缓冲区。

启动时输出 `GrayDetectionV2BuildInfo()`，应读到 `GrayDetectionV2 V6.3 S2; API GrayDetectionV2; native C++17; OpenCV 4.4.0; DLL 2.2.0.0`。原工程若通过导入库链接，首次切换库名时更新头文件引用与链接依赖，重新链接 EXE 或实际引用它的插件 DLL。若通过 LoadLibrary 或 P/Invoke 显式加载，更新模块名为 GrayDetectionV2.dll。本版将类名从 `CrackV4Detector` 改为 `GrayDetectionV2`，C 函数与结构体的前缀从 `CrackV4` 改为 `GrayDetectionV2`，公开常量前缀从 `CV4_` 改为 `GRAYDETECTIONV2_`。原有 21 个函数的序号、参数顺序和结构体布局沿用。按名称动态加载的程序需同步更新 GetProcAddress 查找名或 P/Invoke EntryPoint。内置原生算法，部署无需 Python。

## 按参考帧初始化，按当前帧读取结果

```cpp
#include "GrayDetectionV2.hpp"

GrayDetectionV2 detector;
// 每个采集序列初始化一次。mmPerPixel 取自该实验的标定。
detector.initialize(referenceGray8, refP1, refP2,
                    GrayDetectionV2::ReferenceMode::Auto, mmPerPixel);

// 每帧更新。curP1、curP2 是本帧实测点。
GrayDetectionV2Result result{};
auto tip = detector.getCrackTipPointCirculate(currentGray8, curP1, curP2, &result);
if (result.tip_confirmed && result.length_confirmed) {
    // tip 是当前原图的 (x,y)，含亚像素 y。
    // result.length_px 是裂纹起点沿识别路径到尖端的弧长。
    // result.length_mm = result.length_px * mmPerPixel。
    auto segments = detector.pathSegments();
}
```

两帧尺寸相同，单通道 8 位，坐标以各自原图左上角为原点。输入上方 P1、下方 P2，测量同一对物理点。未提供当前实测点时，C++ 可调用 `getCrackTipPointCirculate(currentGray8, &result)`，C 接口可把当前点指针置为 NULL，由 DLL 估计运动。全帧对照采用逐帧实测点，自动估计另作接口冒烟测试。参考模式 0 由调用方指定干净参考，1 要求参考帧检出裂纹，2 自动判断。业务逻辑以确认标志判断有效性。

C 调用顺序为 `GrayDetectionV2DefaultConfig`、`GrayDetectionV2Create`、逐帧 `GrayDetectionV2Process`、`GrayDetectionV2Destroy`。设置配置中的 `mm_per_pixel` 和结果结构的 `struct_size`。需要路径时在下一次 Process 之前调用 `GrayDetectionV2CopyPath`，先传空缓冲查询点数，再传入已分配的缓冲区。

## 验证组C固定材料选区

常规工程用原图和点对。要复现封存的验证组C验证条件，在启动测试进程前把环境变量 `CRACKV4_V512_MATERIAL_POLICY` 设为对应 JSON 的绝对路径。该变量名沿用旧 SDK，每次创建句柄时读取。验证组C原始点使用[固定材料框](../../../output/verification/v63_dll/group_c_original.json)，亮区点使用[固定材料框和亮区点规则](../../../output/experiments/v58_material_group_c_r07/freeze.json)。两种条件均传原始采集图和原始点对。其他实验启动进程时清除此变量。

## CMake 构建和算法回放
