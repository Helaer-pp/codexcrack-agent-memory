# CrackV4.dll · V5.12 S4 · Windows x64

将 `bin/CrackV4.dll` 与 `bin/opencv_world440.dll` 放在调用程序的可执行文件旁。DLL 使用原版 CrackV4 的 C 接口、调用约定和结构体布局。已有链接程序可以沿用原来的函数名和导入库。新建 C++ 工程可使用本包的头文件与 `lib/CrackV4.lib`。运行环境为 Windows x64、Visual C++ 运行库和 OpenCV 4.4.0，算法在 DLL 内原生执行。

## 输入与输出

调用 `CrackV4DefaultConfig` 后设置参考模式与毫米/像素比例。将参考帧、参考帧上的两个点交给 `CrackV4Create`，每个序列持有一个句柄。图像为单通道 GRAY8，stride 为每行字节数。点使用原图像素坐标，P1 在上、P2 在下。V5.12 追踪沿图像向右生长的裂纹。每帧调用 `CrackV4Process`，传入当前帧及对应点，或传空指针使用原有自动运动估计。每次写入结果前填写 `result.struct_size = sizeof(result)`。

`tip_confirmed` 表示尖端有效，`tip` 为当前图坐标，未确认时返回 (0,0)。`length_px` 是根点至尖端的完整折线弧长，`observed_length_px` 对应剔除末端推断桥接后的折线，`length_mm` 按配置标定换算。读取长度时检查 `length_confirmed`。使用 `CrackV4CopyPath(handle, 0, ...)` 获取全路径，用 observed=1 获取观测段；空缓冲先查询点数。`CrackV4GetBaseline` 只读缓存；`CrackV4LastJson` 读取当前结果或错误；最终调用 `CrackV4Destroy`。原结构中的时间字段以毫秒为单位。V5.12 独立判定每帧，历史版本的时序票数和分块统计不用于尖端决策。

参考模式 0 表示调用方声明干净参考，模式 1 要求识别出参考裂纹，模式 2 自动判断。通过 `CrackV4BuildInfo()` 可确认已加载 V5.12。包内 include 目录的四个头文件来自最初的冻结 SDK。

## 验证组C亮区实验的复现

该实验在上游参考配准之后额外选取材料窗并校验亮区点对。普通部署使用原始帧和点对即可。需要复现验证组C冻结实验时，在启动调用程序前，给该进程设置环境变量 `CRACKV4_V512_MATERIAL_POLICY`，值为包内 `profiles/group_c_bright.json` 的绝对路径。继续传入实验的原始采集帧及原始跟踪点，由 DLL 在内部求亮区点及材料窗。配置在创建句柄时读取一次。对其他实验使用默认设置，确保新进程没有继承验证组C配置。该配置是实验对应的固定操作员选区。

从 SDK 根目录启动示例时可执行如下 PowerShell 设置。

```powershell
$env:CRACKV4_V512_MATERIAL_POLICY = (Resolve-Path '.\profiles\group_c_bright.json').Path
```

## 示例与验证

示例程序按顺序接受参考 BMP、当前 BMP、参考 P1/P2 和当前 P1/P2 的八个坐标。示例采用原始 C++ 包装类。构建示例时，可将 CMake 变量 `OPENCV440_SDK` 指向本地 OpenCV 4.4.0 build 目录。完整回放结果见 `verification/REPORT.md`。V5.12 的冻结实验未通过算法替换验收，尤其要复核三点弯第 248 帧。
