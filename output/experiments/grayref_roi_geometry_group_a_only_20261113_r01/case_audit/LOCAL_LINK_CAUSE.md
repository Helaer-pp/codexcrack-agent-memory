# GROUP_A113：缩小搜索区导致邻接匹配改变的具体位置

仅对已封存的GROUP_A推理结果做事后只读检查，未重跑检测、改参数或读新GT。

原A的合格路径有73个观测节点；B/C中这73个节点全部仍在搜索mask内，也全部仍是保留节点。因此这例不是人工尖端被ROI排除，也不是这些路径节点被直接删掉。

原A同一片段包含相邻节点 `(997,1143) → (998,1145)`。B/C的搜索mask释放每列候选容量后，`(998,1142)` 这个原本未进入A保留节点集合的局部峰被保留：其冻结融合证据约1.0556，原`(998,1145)`证据仍为2.7222，未改变任何灰度值或分数。

冻结的 `fragments()` 按 `(纵向距离, -当前证据, y, previous_y, fragment_id)` 排序，并施加一对一相邻匹配。新点`(998,1142)`距前点只有1px，原后继距前点2px；所以新点先占用前片段，原`(998,1145)`转成新片段。两者在B的片段ID分别85/197，在C分别14/116，而原A同属712。下一列原路径`(999,1147)`仍随新片段延续。

这是可复核的首次连接变化，说明“所有原节点存活”不保证“原路径存活”。它支持ROI通过候选容量与冻结一对一连接产生副作用的解释，不证明全部失败只有这一个原因，也不授权本轮改连接器。

原始局部节点、证据与片段ID见 [local_fragment_neighbors_113.csv](local_fragment_neighbors_113.csv)；各候选存活检查见 [A_good_path_survival.csv](A_good_path_survival.csv)；新增成功与损失同时见 [GROUP_A_CASE_FINDINGS.md](GROUP_A_CASE_FINDINGS.md)。
