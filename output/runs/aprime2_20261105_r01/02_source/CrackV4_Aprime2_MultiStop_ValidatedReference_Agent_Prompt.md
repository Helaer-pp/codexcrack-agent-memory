## 3. 工作包 A：从冻结 A 内部提取“少量有意义的停止候选”

### A0. 首先审计实际 DP/停止路径

1. 逐函数定位 seed/ROI、ridge response、DP 状态转移、tile 成功/失败判据、延伸坐标映射、`evidence_ended`、方向歧义、时序验证、最终 `measure()` 与 V2 输出。
2. 确认目前有哪些数据已经在计算中但被丢弃：每 tile 最佳/次优累计分数、增益、支持点数、局部暗谷强度、法向响应、方向和有效像素比例。列出“已有可复用/仅需旁路采样/必须额外计算”，估算每项耗时与内存。
3. 设计最小侵入式 instrumentation：**优先在独立克隆 C++ 源文件/研究库中开启**，不改原 DLL；对照 `A`/`instrumented_A` 输出、float64 路径与状态 bitwise 一致。
4. 任何旁路候选不可反过来改变 A 的 DP 状态、早停规则、时序缓存或输出。初始化及帧顺序严格一致。

### A1. 构造原路径上的一维证据序列（仅作候选提议）

将原 A 路径按弧长 `s` 与原图双精度坐标关联；原始路径为主，避免重新在全图运行 DP。逐段记录：

- `R(s)`：当前暗谷/脊线强度和局部噪声归一化信号；保存中心线值与**依据估计线宽、成像分辨率确定的法向容差内峰值**，避免中心线偏移导致假断裂；
- `U(s)`：支持点密度、tile 增益、残余无效像素比例；
- `G(s)`：局部曲率、切线转角、路径反折和离散跳变；
- `W(s)`：法向暗谷半宽、邻域前后响应剖面与稳定性；
- `B(s)`：局部高响应竞争支路/第二路径的代价差（**仅从现有 DP 状态及局部小范围计算得出**）；
- `T(s)`：已发生历史帧对应末端附近证据，只有几何可比较时有效；**不强制单调增长**；
- `Q(s)`：有效像素、采样精度、ROI 边界和证据可观察性。

上述序列使用统一确定性估计公式；禁止将排除组X 473 的坐标、tile 编号和某个测试像素长度编码进规则。**如果某量无法从现有代码低成本获取，应标记缺省并继续 H1，不因缺项虚构。**

### A2. 定义有限、多样的候选产生机制

必须包含（按是否适用生成，不必强行补齐所有类型）：

1. `A_ORIGINAL`：A 原始合法尖端；**bitwise 保留，不允许被剪枝**。A 无 valid 尖端时保留 `A_NO_TIP` 状态；研究可提出候选但不冒充 A 输出。
2. `SUSTAINED_SUPPORT_CHANGE`：连续的前后支持度差异/变化点；使用稳健窗口统计、有效区间长度和噪声估计，**不是一次低灰度即截断**。
3. `BRANCH_OR_GEOMETRY_CHANGE`：tile 方向、竞争路径或曲率证据突然变化的位置，作为可能从裂纹跳至纹理的入口；**弯曲本身不是停止证据**。
4. `LOCAL_ENDPOINT_REFINEMENT`：上述候选的局部像素/亚像素调整；必须另存“未经调整候选”供审计，不能追求亚像素精度来掩饰目标身份错误。
5. 可选 `FORWARD_SUPPORT`：A 早停或无有效尖端时，在紧邻已知可信路径尾部的小范围内寻找延伸假设，**不得第二次全图 DP**。

**每个早停候选都要有一个“裂纹继续延伸”竞争假设**，包括匹配真实长裂纹。保留局部最有区别的候选，使用依赖线宽/空间分辨率的合并距离；全局 `K` 上限**建议先沿用历史 K≤12 的研究预算**，实测消融再冻结更紧上限，绝不可对 GT 选 K。每个候选保存产生原因、相关证据窗口、CPU 代价、位置和可观察性。

### A3. 必须区分两类主路径失败

- **类 I：真尖端在 A 的现有路径上或其法向小范围内。** 多停止候选理论上可能解决，评价候选 recall 和候选数之间关系。
- **类 II：DP 在上游分叉就选错路，真尖端不在其路径邻域。** 单纯截短不能解决；将其标记为 `PATH_DIVERGENCE`，先量化比例，再决定是否需要从**已有 DP 备选状态**取有限个分叉候选。不得因为类 II 存在就无条件启动多条完整 DP。

### A4. H1 独立验收指标

- 原 A valid 正例中的 `A_ORIGINAL` 保留率、原图 double 坐标一致性 = 100%；
- 新受控 DEV 中 `GT ≤8px` 候选**oracle 上界**、按故障族统计的正例覆盖、每个 case 的候选多样性、候选几何距离分布、必要候选遗漏原因；
- 强假尾候选中：真实短端附近是否出现早停候选；匹配真长中原长端是否仍在候选池；
- 曲线、弱暗线、静态纹理交叉时的候选召回；
- 每帧候选个数、生成延迟、额外内存与已存在 A 结果零变化。

**Oracle 指标只用于证明候选存在，绝不能当成在线决策精度。**

### B3. 几何变换与有效性：局部而非整帧一票通过

3. 如必要且可用数据充分，再研究**有界**局部旋转/仿射，必须在独立 HOLDOUT 上显著优于简单模型，否则回退或 UNKNOWN；
4. 对每个候选建立 `validity_domain`（可观测材料位置/凸包、置信误差和覆盖比例），严格区分**区域内插值**与无依据外推；
5. FIT / HOLDOUT 必须按**空间分离块**切分，不允许重叠 patch 共享像素后假装独立；检查剔除少量块、图像亚像素扰动后的结果稳定性；
6. 参考/当前像素亮度使用 FIT 的稳健偏置/增益模型，HOLDOUT 独立验收残差、MAD 和裁剪比例；亮度模型失败可以只使用可信几何字段，不能悄悄使用差分。

**输出至少四个独立状态**：`GEOMETRY_VALID`、`PHOTOMETRY_VALID`、`INCREMENT_OBSERVABLE`、`OWNERSHIP_INFORMATIVE`，各自可为 `SUPPORTED/CONTRADICTED/UNKNOWN`，不得将整帧 pass 直接升级为候选尖端归属 pass。

### B4. 沿候选竞争区间计算“新增暗线”而非原始差分

在局部法向剖面计算：

```text
Vcur(s): 当前图像暗谷对比（两侧材料灰度 - 中心暗线灰度）
Vref(s): 几何配准并通过光度验证后的参考暗谷对比
DeltaV(s) = Vcur(s) - Vref(s)
D(s): 经补偿参考与当前的局部变化（仅附加诊断）
SNR(s): 稳健噪声归一化统计
O(s): 此处是否真正可观察、配准/光度/采样是否可信
```

- 比较短候选 `C_short` 到长候选 `C_long` 的**整个争议段**；独立统计 `NEW_CHANGE_SUPPORTED`、`STATIC_TEXTURE_RISK`、`UNKNOWN` 的连续区间、空洞与支持比例。
- `NEW → STATIC_RISK → NEW` 可能是真裂纹穿越静态纤维，**不自动截断**；`NEW → 长区间STATIC_RISK且参考可观测` 更符合假尾假设，但仍需其他独立证据。
- “不存在新增变化”只有在**局部检测灵敏度充足、配准/光度通过、争议段被足够覆盖**时才可解释为证据缺失；否则 UNKNOWN。
- 对几何/亮度参数在估计误差范围内扰动，若短/长证据排序翻转，输出 `EVIDENCE_UNSTABLE`。
- 参考配准可信≠物理裂纹归属可信；不要重复 C2 的 `REFERENCE_OWNERSHIP_TRANSITION` 优先覆盖 A 的错误。

### B5. H2 独立评估指标

逐试件与逐材料特性输出：局部参考可观察率、联合几何/光度有效率、**候选争议段长度加权可观察覆盖率**、错误接受的几何变换率（仅有 GT 的控制集）、误配准量 P50/P90/P95、留出残差、有效块空间分布、饱和/低纹理失败原因、每帧匹配块数与耗时。

- 使用历史 337/3029 作为**同口径信息可用性的参考基线**，不能要求无真实 GT 的组“配准物理正确率=100%”；
- 研究目标是让旧零支持组中的更多图像出现可信**局部**证据，但不应靠“更宽容的通过标准”达成；
- 加入已知 0.5/1/3/5px 平移、局部光照变换、局部仿射、重复纹理、遮挡、压缩、饱和及参考本就有裂纹的独立受控 GT；
- 如果参考支持仍然只集中在两组，必须按 `H2_NOT_GENERALIZED` 报告，继续 H1 而不启动不可信的尖端替换。

## 5. 工作包 C：独立的短/长尖端假设比较（仅在 A/B 有充分证据后启用）

### C1. 不是“再加一个统一尖端得分”

每对有实质差异的候选 Cshort/Clong，都要显式保留两种解释：

- `H_STOP`: 裂纹在短候选结束，之后是静态纹理、无关暗线或不可辨识区域；
- `H_CONTINUE`: 真实裂纹延伸到长候选，期间可能变浅、弯曲、经过静态纹理。

证据拆分为：候选前段连续性、争议区新暗线证据、争议区可观察性、分叉几何、尖端前后局部形态、可比历史末端、静态纤维穿越后是否**再次出现可信新增证据**。

**不使用固定“原点距离最短/最长”“第一个静态纹理处”“单点最大暗谷跌落”来直接选尖端。** 模型可以是透明、有限参数的规则/序贯似然评分，但所有权重/阈值/优先级必须新 DEV 固定并可逐项消融。

### C2. 安全与可审计的研究决策

至少输出：

- `A_UNCHANGED`：当前没有额外充分可信证据，A 官方输出保留；此状态不等于 A 物理正确。
- `RESEARCH_RELOCATED`：研究版认为候选间的**可观察争议段**支持改变尖端；详细列出支持与反证。
- `RESEARCH_UNCONFIRMED` / `AMBIGUOUS`：两种假设难分或输入信息不足；独立于生产 A 状态。
- `NOT_OBSERVABLE` / `BUDGET_EXHAUSTED`：真实有效域或计算量不足。

**严禁在真实六组运行时根据试件名特殊回退/特殊选择**。允许的 A 原输出保护是统一、可审计的研究政策；不能把所有输出退回 A、然后声称“零损坏证明安全”。

### C3. 必做反事实与反例

- 共享当前图像/P1P2、不同参考/不同 GT 的真假长尾配对；参考关掉/交换/遮挡后，若参考真有贡献应出现可解释的消融差异。
- 真实裂纹穿越静态纤维、划痕、孔洞边缘的 `NEW→STATIC→NEW`；避免重演 C2 的 >160px 错改。
- 弱裂纹、渐浅尖端、S 弯、55°/75° 弯、长裂纹、无裂纹静态暗线（阴性）、低纹理/饱和/参考已有裂纹。
- ROI 放大 1.5× 且固定候选/采样/审核窗口的反事实；另做**重新运行搜索**的反事实，二者不得混同。
- 小配准扰动、局部坏块删除、候选顺序打乱、位深/光度小扰动，检验最终决策是否稳定。

## 6. 先修复工程 DEV 的“目标故障激活”，再做任何成功声明

### D0. 为什么本阶段是硬门槛

上轮 A′ 工程 DEV 的 12 对假尾 A 并没有 >32px 的强错误长尾，匹配真长 A 又 0/12 正确。这种场景不具备鉴别新方法能否修复 A 异常且保留真长的判别力。**禁止重复这种无效 TEST 后直接发布算法。**

### D1. 新 DEV 生成器需要的机制

先设计不同于旧傅里叶相位/反应扩散参数组合的**新独立材料背景过程**，以及具有物理可解释性的线状暗谷形成机制。具体要包含：

1. `STRONG_FALSE_TAIL`: 真实裂纹在近端止住，但静态参考纹理与裂纹主体形成连续高响应路径，冻结 A **实际确认**远端，二维误差例如 >32px；
2. `TRUE_LONG_MATCHED`: 当前图像和基准点与对应假尾配对**逐位相同**，参考图改变、程序真尖端在远端；在可观察帧中冻结 A 对远端通常能够正确定位（≤8px）；
3. `STATIC_CROSS_THROUGH`: 真实裂纹中途穿过参考图已有划痕，穿过后仍延伸；
4. `WEAK_FADE`, `S_CURVE`, `CURVE_55_75`, `STATIC_LINE_NEGATIVE`, `HOLE_MOTION`, `LOW_TEXTURE`, `SATURATED`, `PHOTOMETRIC_CHANGE`, `ROI_BOUNDARY`, `LOCAL_MISREGISTRATION`；
5. 各族覆盖不同尺寸/线宽/曝光/纹理密度，具体组合以**预注册**方式固定，不按试件名称人工分支。

**DEV 激活判据**：在生成器开发阶段实际运行冻结 A，逐例统计 A 假长尾的强错误数量、匹配真长的真实远端正确数量、两侧同时可观察的独立配对案例数。要求先出现足够数量的**独立激活 pair**；建议最低 ≥12 个独立激活 pair，并跨≥3种不同背景过程分布（这是研究组织目标，不是统计显著性保证），具体阈值在见到新 TEST 前冻结。将全部生成及筛选机制详细记录；**旧排除组X帧只能提醒机制，不能复制像素或在生成器内写死正确尖端**。

如果无法构造满足“假尾 A 真错、真长 A 真对”的 pair，先报告 `ACTIVATION_FAILED`，可以继续单项技术诊断，但**不得宣布 H3 成功、不得运行名义上的正式 TEST**。

### D2. 防止选择偏差与结果泄漏

- DEV 允许通过错误分析修改研究算法、生成器和策略，但所有 DEV 结果标记 **EXPOSED_DEV**；
- TEST 必须是**新背景种子/参数族**，采用在 TEST 生成前冻结的算法、生成器、评价器、门槛和预定样本清单；生成前冻结与冻结后的 GT 封存分别出 SHA；
- TEST 只执行一次，且不能按 A 或新算法的表现筛掉失败 case；可用激活统计**描述** TEST 是否具有判别力，但不能使用评测输出后重新生成另一批称作“同一 TEST”；
- 真假尾 pair 的共享当前图像采用原始字节 SHA 检查；每个 pair 全部帧按独立 `pair_id` 作为聚类单位，不能把每帧或两个共享图像当成独立样本；
- 同时报告**全量预注册 TEST**和预注册机制子组，不能只展示激活子集的好结果；无足够激活则结论 `TEST_NOT_DIAGNOSTIC`，不是通过。

### D3. TEST 与统计

对预注册正例、阴性、不可观察正例分别评价：

- A、A′2 的 `tip_valid`、二维尖端误差分布、≤8px 正确数、覆盖率、条件 MAE/P95，且计算**同一配对共同确认**误差；
- 全部可观察正例的**预注册拒绝惩罚损失**（例如沿用旧 32px 惩罚/64px cap，但若更换须先锁定、解释），不要通过大量拒绝降低 MAE；
- `A_correct_revoked`, `A_correct_changed_wrong`, `A_wrong_corrected`, `C_new_correct`, `A_false_long_fixed`, `true_long_broken`, `negative_false_confirmed`, `catastrophic_>160px`；
- 匹配 pair **真假两侧同时正确**的独立 pair 数与帧数；
- **candidate oracle** 与 **actual selection** 必须分开；
- 按独立 case/共享当前 pair 做 paired bootstrap 95% CI，报告绝对差、校正后的配对差和错误族，不凭单帧数量夸大样本量；
- 已曝光真实六组仅报告研究改动、疑似异常与参考可信覆盖，没有人工物理 GT 不给“真实 MAE”或改进帧数。

## 7. 预登记 Gate 与必要的失败退出

按研究阶段逐项判定，不得将一条未通过的门槛解释为“开发已基本完成”。阈值如在研究中改动须留 DEV 变更记录，**正式 TEST 前全部冻结**。

### Gate 0：冻结 A 守恒

- 新分支与冻结 A 的源文件、DLL、头文件 hash 有留档；原官方模式 **3035/3035** 状态/valid/坐标/旧弧长/float64 路径完全相同（如仅部分原图可用，报覆盖范围和 N/A，不可虚报）。
- 诊断旁路不得污染 A 正式状态、时序历史、图像缓存；A 官方结果应随同研究结果单独导出。
- Gate0 失败 → 停止进一步效果宣称，先修复回归。

### Gate A：停止候选有效

- 每一帧保留 A 原始尖端，候选产生可追溯且严格有界；
- 在**已实际激活的**假尾 DEV 里，短端出现有意义候选，同时真长远端不被候选剪枝；给出按 case 的 oracle 上界；
- 观察不到可用短端候选时记录 `CANDIDATE_RECALL_FAILED`，不要通过降低最终确认门槛掩盖。

### Gate B：参考可信性/泛化

- 参考配准的 GT 控制误匹配率与误差**不得因提高覆盖而退化**；提高的有效证据要覆盖候选争议区，而非仅整帧的无关区域；
- 逐组报告零支持组是否仍为零、与既有 A′ 337/3029 **同任务口径**的结果，并报告候选区间新口径覆盖；
- 同一套规则，不存在按组特设；弱信息正确返回 UNKNOWN。达不到证明时 `REFERENCE_NOT_GENERALIZED`，只保留 H1 成果。

### Gate C：尖端选择效果（在新 DEV 确认后才允许锁定正式 TEST）

- 预注册目标至少包含：总体正确尖端数**严格多于 A**，总体惩罚损失下降、阴性误确认不得增加、已正确 A 不发生系统性误撤销/误改、真假尾双方同时正确改善；
- 绝对禁止把已有已知 `>160px` 错改风险当成可接受的微小误差；需要显式“灾难性错改”门槛，推荐以 **0 起步**，并解释有限测试不能证明将来零风险；
- 可设置严格 `A_correct_changed_wrong==0` 作为候选生产准入门槛，但不应因此把没有做任何替换的版本宣称有效；**必须有实际正确改进且整体净收益为正**。
- 独立 TEST 如未通过任何关键条件 → `KEEP_A`，研究价值可以单列但不发布。

### Gate 15Hz：原生完整性能

- 只在算法效果过关后考虑新 C++ 生产候选；若为了工程可行性提前做原生性能原型，必须与生产 A 严格隔离；
- 记录 `Process + GetResultV2 + CopyPath + A′2 候选/参考/决策 + 内存分配` 的**完整**时间，逐帧最大值、P50/P95/P99、机型/线程/编译器/缓存/冷启动、重复运行；
- **所有**要求帧 ≤66.67ms；必要时优化 A 内可复用计算而不是在 63.9ms 的最慢帧后无条件增加新循环；
- Python 耗时、视频 FPS、仅 A 耗时均不能替代此门槛。无法运行完整原生核心则写 `NOT_TESTED`。

## 9. 实现次序与代码组织

**推荐按以下顺序执行，避免整轮结束后只得到“Gate1 未过、尖端没有做”。**

1. **P0 审计与复现**：建立文件/版本/数据清单、编译与运行命令、原 A bitwise 基线和最慢帧性能记录。
2. **P1 并行支线 A**：从原生 A 的 tile/DP/路径提取候选，做新 DEV oracle 召回评估，报告因搜索路径走错而无法覆盖的案例。
3. **P1 并行支线 B**：修复参考材料选择器和候选区间查询，严格同口径检验几何/光度/局部有效性，不放松后验审核。
4. **P2 先构造有判别力的新 DEV**：运行冻结 A 校验强假尾**实际发生**、匹配真长**真实可追踪**，给出激活率，失败则继续 DEV 生成器研发或终止 H3，不得跳过。
5. **P3 两支线独立消融**：`A_only`、`candidate_only`、`reference_only_shadow`、`candidate+reference_no_select`、`full_decision`；分开记录效果与副作用。
6. **P4 研究尖端决策**：只在新 DEV 中校准，重点防误截断真长/静态纤维交叉，明确 UNKNOWN。
7. **P5 冻结/独立 TEST**：先锁算法/生成器/评价器/阈值与输入哈希，后一次执行，按预注册 Gate 判决，不得返工后继续称原 TEST。
8. **P6 原生实时可行性**：研究阶段即记录边际 C++ 时间与缓存占用，效果达标再构建独立候选并测完整 15Hz。
9. **P7 交付失败证据**：即便没有通过也必须交完整源码、失败原因、统计 CSV 和下一轮最小建议；不能仅返回 `KEEP_A` 一句话。

### 明确终止规则

- `Gate0` 失败：立即先修复冻结 A 回归，不讨论优化是否成功；
- DEV 未激活 A 错误强假尾或无法保护匹配真长：`ACTIVATION_FAILED`，不开展正式效果 TEST；
- H1 不产生有意义候选：`CANDIDATE_RECALL_FAILED`，转向诊断有限分叉，而非强制调参；

- H3 只改善条件 MAE 但损坏大量已正确 A：`KEEP_A`；
- 原生时间不能达标：`RESEARCH_ONLY` 或 `NATIVE_NOT_TESTED`，不改生产 DLL。
