# 原黄金回归为什么不能直接代表全序列同一帧结果

只核对已保存的输入/输出，没有额外检测调用或参数修改。同一参考BMP与`3 (175).bmp`的字节SHA完全相同；该文件在完整时间序列中是frame_id=237，不是序列175。

黄金回归使用任务书给定参考P1=(2243.75,2247.50)、P2=(2260.00,2431.25)，原NCC得到当前P1=(2242.75,2252.50)、P2=(2259.00,2435.25)。联合T10端点=(2423,2344)。

全序列按用户已有跟踪记录：参考P1=(2248.46,2250.77)、P2=(2244.49,2439.53)，当前P1=(2248.22,2256.98)、P2=(2243.74,2442.37)。联合T10端点=(2255,2282)。

这是相同图像、不同P点输入。冻结V1的ROI、初始x和中心先验由P点直接确定，因此黄金回归通过不能保证另一套实际跟踪P点下结果相同。没有将任务书那一对手工回归点套用到整组，也没有为了匹配黄金端点替换实际点记录。该对照说明输入适用性问题，不能把批量端点不同误写为黄金回归失败。具体ROI和坐标见同名JSON；不从这个验证案例反向修改V1规则。
