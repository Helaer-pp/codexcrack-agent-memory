# CrackV4 新样本过度追踪：根因验证、受控修复与最终交付任务书

> **用途**：将本文件连同最新 CrackV4 工程、历史五份报告、原四组数据、新增「排除组X白板样组1」完整原图序列和现有叠加截图/视频交给代码 Agent。你是负责 C++17 / OpenCV 4.4、工业裂纹中心线跟踪、实验验证、Windows DLL 接口与实时性能的高级工程师。
>
> **必须执行**：核实输入与源码 → 冻结当前输出 → 复现失败 → 定位真实根因 → 实施最小可回退修复 → 五组完整时序回归 → 算法性能基准 → 实际生成视频与逐帧结果 → 输出能被审计的结论。**不要只提供设计建议或伪造结果。**
>
> **本轮第一优先级不是“让更多帧被确认”，而是消除“越过真实裂纹终点仍沿背景噪声延伸，并把错误长路径确认成完整长度”的风险，同时保留短裂纹、弱裂纹和真实长弯曲裂纹的检出能力。**

## 0. 不可违反的原则

1. **传统 CV，暂不引入神经网络**。保留现有参考图、基准点配准、局部响应/黑帽、seed、DP、tile、root、terminal、temporal 主架构，除非根因分析给出明确证据，不做全面重构。
2. **仅以原图像素坐标、像素中心线弧长和有效性作为测量输出**。毫米换算交由外部软件，旧 ABI 为兼容可保留相关字段。
3. **算法计算至少 15 Hz**：单帧算法调用预算约 **66.67 ms**。本轮核心计时不含图片读盘、解码、显示、绘图、视频编码；包括实际用于生产的配准、DP、路径/尖端检查、结果生成及必要回退。正常、未确认、错误、回退帧都必须入统计。
4. **不能用拒绝所有疑难帧来“解决误检”**。必须同时比较错误确认数、真实裂纹召回、首次确认延迟、尖端及长度误差、有效测量覆盖率。没有独立人工真值时不准冒充有真值。
5. **不能使用数据集名称、frame_id、文件名、固定长度上限、固定朝右/朝下、固定停止像素点来写针对性补丁。** 优化必须根据图像中的可解释证据生效，允许真实裂纹转弯、变浅、短时遮挡、可见长度回落。
6. **新行为必须显式开关、可回退**；原兼容 API、旧版二进制接口布局及旧配置不静默修改。对五组独立实例按真实帧序完整回放，不能把之前回放结果当人工真值。
7. **不得把错误路径截断后自动称为“真实物理尖端”**。若只是失去图像证据，保留“可信可见路径 / 不确定末端”；只有终端独立证据充分才输出 `tip_confirmed=true`、`complete_length_valid=true`。

## 2. 必须准确复现的两个新样本异常

### Case A — 疑似无证据长候选路径，但尚未有效确认

- 排除组X白板样组1，截图标识：`图片 52/524，num=51`。
- 截图顶部显示：**尖端原图坐标 `(0,0)`、完整裂纹长度 `0 px`、尖端有效 `0`、完整长度有效 `0`**，检测时间约 36.26 ms。
- 可视问题：中心孔右侧延伸出一条明显向上弯曲的**橙色候选轨迹**；左侧原图未见与整个长曲线相符的清晰暗裂纹。
- **重要判断**：此案例不应直接列为“错误确认的尖端”，因为截图中有效位为 0；需要检查候选生成、诊断输出与视频绘制是不是把未确认路径表现得像真实裂纹。
- 必须返回：候选路径来自哪个 seed / tile、每段证据如何、停止原因、为何最终 invalid，以及其是否污染 `previous/history` 或下一帧搜索；若没有进入正式测量，明确区分“候选轨迹可视化问题”与“真实误报”。

### Case B — 明显裂纹之后可能继续沿背景过度追踪且被确认

- 排除组X白板样组1，截图标识：`图片 474/524，num=473`。
- 截图顶部显示：**尖端有效 `1`、完整长度有效 `1`、尖端坐标约 `(2344.05,2409.42)`、完整长度约 `1084.13 px`**，检测时间约 36.75 ms（均以原始输出复核为准）。
- 左侧原图可见：中心孔右侧一段较清晰的**近水平黑色裂纹**。右侧叠加路径继续弯曲向右下方，疑似明显偏离真实黑裂纹，末尾还可能被标记为有效尖端。
- **严重性更高**：若正式输出的有效路径确实包含偏离真实裂纹的长尾，则是错误有效测量，而不是简单的候选路径显示问题。
- 必须从最新的 **`GetResultV2` / 完整路径数组 / `tip_confirmed` / `complete_length_valid` / `tracking_endpoint`** 逐一核实：截图中的**红色（已确认路径）与橙色（候选路径）究竟哪些像素属于正式测量**，不能仅凭颜色想象整条曲线都计入了 1084.13 px。
- 若确认为正式输出错误，应定位**首次偏离真实暗裂纹的原图坐标、tile 索引与起始帧**，以及最初使错误长尾获得 `terminal accepted` 的具体证据。

## 3. 根因定位：先证据，再修改

必须提供一份按实际源码函数/行号追溯的诊断报告，至少验证下列假设；不能只罗列猜测：

### H1：seed/入口是否选择错误

核对 `forward`、起点、根部位置、入口掩膜、参考已存在裂纹状态、初始 seed 质量。新样本中中心孔附近可能有黑色圆孔及背景杂散线，检查是否将孔边/背景纹理当起始裂纹；检查方向固定设置与 P1/P2 排序是否对应。

### H2：DP 在低证据背景仍可选择“最优但错误”的路径

对每个 tile、每隔固定弧长的小段和末端附近采集：`tile_id,local_origin,local_direction,seed_score,blackhat_response,reference_difference,positive_support_fraction,centerline_darkness,cross_section_contrast,local_noise_MAD,gap_count,weak_run_length,curvature,turn_angle,candidate_points,stop_reason`。字段以源码真实可计算的指标为准，无法直接取得的标为新增诊断，不得谎称原算法已产生。

明确区分：

- **当前存在暗线**（trace evidence）：当前图沿候选线与两侧背景相比是否形成稳定暗谷、是否具有合理线宽和跨截面结构。
- **相对参考新增/增长**（novelty evidence）：注册后的当前图与参考图之间是否出现对应暗线差异；参考原本带裂纹时不能机械地要求所有有效路径都具有强新增差分。
- **背景伪线竞争**：仅凭黑帽或局部 DP 相对得分高，是否就能在缺少绝对裂纹证据时无限继续。

检查 tile 接续、`d=-2..2` 或实际允许的局部转向、转角/曲率积累、路径平滑是否将噪声连接为假弯曲线；不得硬编码“裂纹只能水平/向右”。

### H3：证据终止与物理尖端被错误等同

检查 `evidence_ended` / 各种 stop reason 的具体触发条件；逐条追踪最终 `tip_confirmed`、`complete_length_valid` 由哪些证据授予。验证原 seed 强度、root 支持、旧路径前缀相似是否使当前**末端证据不足**时仍被确认。

明确回答：在 Case B 中，**为什么是最后的弯曲尾端而不是原图黑裂纹的末端被输出**？如果当前缺少足够证据确定物理尖端，应解释为什么当前状态没有降级为 `tip_uncertain`。

### H4：图像配准 / 外部点 / 参考模式影响

对比外部双点（如有）与 AUTO、是否保留 `refine_anchor_motion`、参考相同点几何残差。若几何正常而路径仍偏离，应将其归为路径/终端问题，不要不断增加配准算法掩盖真正根因。

### H5：时序反馈污染

比较完整闭环序列与**单帧独立运行（诊断性质，不能替代闭环验收）**；检查 `previous`、历史路径、合格尖端观察记录、候选误路径是否影响下一帧 seed 和终点确认。记录错误路径的首次出现、首次正式确认、撤销/持续帧数。

### H6：视频叠加或坐标转换错误

核对展示的图像是否经过旋转、缩放、ROI 裁剪、分屏变换；从原生 V2 路径点直接映射至原图验证，排除“画错位置但原始坐标正确”。若是绘制错误，应仅修正绘制，不无谓改检测主算法。

### 根因结论必须用证据表

| case / frame | 最初出错阶段 | 直接证据（源码、日志、灰度/响应图） | 路径是否进入正式测量 | 排除的假设 | 修复目标 |
| --- | --- | --- | --- | --- | --- |
| Case A / 51 | 待实测 | 待补充 | 应先核实 false/true | 待核查 | 防伪候选/时序污染 |
| Case B / 473 | 待实测 | 待补充 | 应先核实 true/false | 待核查 | 不错误确认超长路径 |

不能在完成这张表之前，一次性叠加数十个阈值或直接更换全部算法。

## 4. 修复设计要求：支持的路径、候选末端、物理尖端分离

仅在根因证实后，选择最小改动并保留消融开关。优先考虑以下实现方向，而非强制全部实现：

### 4.1 局部路径支持审计 + **最后可信前缀**

- 对已有 DP 候选路径做轻量分段质量检查，形成 `supported_prefix` 与**不受支持后缀**的分界；尽量复用现有 tile、黑帽和差分缓存，不重新执行整图 DP。
- 采用稳健的局部噪声基准、局部相对对比/横截面结构及参考差分；避免绝对灰度阈值在亮度变化、不同材料和弱裂纹上的泛化失败。保留参考已带裂纹模式。
- 连续弱证据要经过**有界的容错区间**判断，允许真实裂纹局部断续/灰度较弱；不得在一个弱像素处立即截断。
- 检查真实连续弯曲裂纹：**转弯越大需要图像证据越充分**，但转弯本身不能成为硬性否决条件。
- **截断位置不等于物理尖端真值**。若终端定位的局部证据不足，返回 `tracking_endpoint`/`visible_path` 与 `tip_uncertain`，不得为了让长度“看起来合理”就伪造 `complete_length_valid=true`。

### 4.2 末端独立验证

检查末端前后支持、局部暗线是否在前方真实消失、是否持续有更远的有效暗线、真实裂纹宽度/方向连续性和缺口遮挡情况。不可用“DP 分数掉下去”单独证明真实尖端。对已知遮挡、饱和和缺失证据，不得输出已确认物理尖端。

### 4.3 时序证据不能自我强化假路径

候选路径与合格确认历史分开；历史根部稳定不证明新末端真实。对于疑似首次出现的过长长尾，保留异常状态与证据采样，不让其成为下一帧更长尾的无条件先验。不得强制可见长度单调增加。

### 4.4 可视化行为单独修复

- 无效尖端时，绝不在顶部显示“完整长度=有效数值”；如真实 ABI 约定无效字段为 0，可保留数值但同时明确显示 `N/A / invalid`。
- `candidate_path` 用低强调度的橙虚线或可选诊断层，不与正式可见路径、确认尖端混色。无裂纹情况下避免让无证据的长候选路径看似已确认。
- 标注原图坐标、图像缩放比例，视频仅用于观察，不是精度真值。

### 4.5 明确的状态与 API 不变式

每帧必须区分：`candidate_path`、`supported_visible_path`、`tracking_endpoint`、`tip_confirmed`、`complete_length_valid`、`registration_valid`、`terminal_status`。若现有 Pixel V2 不能原样表达全部诊断，新增**可选版本化字段/诊断查询**，不能改变原有结构大小或旧函数语义。

**关键不变式**：`complete_length_valid=true` 必须同时满足根部有效、实际测量路径端点有独立可信终端证据，且完整长度由**该条有效路径的像素弧长**计算；不能把 candidate 的尾段计入有效长度。当前结果无效时，不得回填历史坐标冒充本帧有效尖端。

## 5. 必做对照、回归与精度评价

### 5.1 配置（相互独立的 Detector，闭环时序）

| 配置 | 用途 |
| --- | --- |
| `FROZEN_CURRENT` | **冻结这次新样本使用的实际 DLL、配置、双点与原始输出** |
| `BASELINE_ANCHOR_SHADOW` | 原四组实测双点和第五组可用的可信点，原推荐 `flags=3572` |
| `CANDIDATE_SHADOW` | 本轮有开关的路径支持/终端改进，生产候选 |
| `CANDIDATE_OFF` | 同一新代码，全部新开关关闭，验证向后兼容 |
| `CANDIDATE_VERIFIED_DIAGNOSTIC` | 仅旁路/独立闭环对照，不因其覆盖下降直接宣布更准确 |
| `AUTO_DIAGNOSTIC` | 仅在必要时检查自动配准差异和误配风险 |

每组数据的参考和配置必须一致，统计按**源 frame_id** 对齐；禁止把参考点变化或坐标系变化当作算法收益。对于第五组没有双点或 GT 的情况，表中如实标注输入差异，不能制造公平对比假象。

### 5.2 五组完整时序

- 四组历史数据完整跑过，**新第五组也完整跑完其真实全部帧**，不能只跑 51 和 473 两帧。
- 逐帧比较状态、根部、候选路径、有效路径、追踪终点、尖端、有效完整像素长度、配准状态、首次确认 frame_id、时序反馈、路径长度及停止原因。
- 专门统计：误长尾出现帧、误长尾长度（有 GT 才叫真实误差）、有效长尾确认帧、无裂纹有效确认、真实短裂纹早期检测、真实长弯曲裂纹被误截断、首次确认延迟、未确认率。
- 四组原先正确的长裂纹/弯曲裂纹/低对比度场景必须专项复核。不能为了 Case B 把所有长/弯曲路径拒绝，也不能靠无条件关闭 terminal 确认获得安全表象。
- 新第五组保留独立挑战数据身份。若用于调阈值，必须明确标记调参子集和**未参与调参的时间段/帧子集**，以避免只对已知的 51、473 两帧过拟合；全部五组仍须全量回归。

### 5.3 人工真值与指标边界（禁止杜撰）

1. 首先检查是否已有独立人工标注的裂纹根部、中心线、真实尖端与可见性。**逐帧双基准点不等于裂纹尖端真值**。
2. 优先建立至少覆盖第五组**无裂纹早期、首次萌生、明显水平裂纹、疑似过度追踪、强曲率/弱对比及末段**的人工复核子集，并覆盖 51、473 及其邻帧；再从四组各抽取正常、难例、长弯曲和有分歧样本。样本数可按实际标注资源调整，但要记录选取策略及未抽样范围。
3. 标注模板至少包括：`dataset,frame_id,crack_present,tip_visible,root_visible,tip_x,tip_y,root_x,root_y,centerline_polyline,length_px_gt,occlusion,overexposure,annotator,review_status`。没有独立中心线，长度 GT 必须留空。
4. 对已人工核实的帧输出：尖端欧氏误差 `MAE/P50/P95/Max`、长度误差 `MAE/P50/P95/Max`、有符号偏差、**过度延伸误差**、误确认率、真实裂纹检出率、确认覆盖率和首次确认延迟；分母分别列清。未确认帧不算“0 误差”，应另列漏检/不可见/不确定。路径偏离可用中心线距离或受支持路径比例，但须明确计算口径。
5. 如果尚无独立人工 GT，必须写 `tip_ground_truth_available=false`，真实尖端/长度误差 **`N/A`**。可同时提供**算法间差异、基准点残差、逐帧诊断、原图比对图和待标注 CSV**，但不可把代理稳定性当实际精度或将原算法输出当标签。
6. 已有合成真值测试要独立统计：支持旧的长弯曲裂纹、快速生长、弱裂纹、预裂纹参考、遮挡/恢复、过曝、无裂纹以及故意构造背景暗线诱导的过度追踪。新合成数据不能替代第五组真实 GT。

### 5.4 显式验收条件

以下均为必查项，不能以总体平均掩盖失败：

- **Case A**：即使仍存在可解释的候选路径，也不允许它污染有效尖端/完整长度或历史；视频清楚标为候选，不冒充检测成功。
- **Case B**：必须检查新候选是否在黑裂纹真实支持区域后停止或降为不确定，**不得继续把无证据尾段作为已确认完整长度**；只有独立 GT 才能宣称截断到了正确物理尖端。
- **四组正常样本**：不得发生无证据的大规模确认覆盖下降、真实弯曲裂纹被截断、原正确长度大幅变化。出现变化必须进入人工复核列表，而非自动判作“优化”。
- **性能**：所有正常/错误/回退/不确定帧均计入，报告 P50/P95/P99/Max 与超预算数量；无外部证据证明准确性提升的重型策略不能启用。
- **兼容性**：旧 C ABI、Pixel V2、ResetTemporal、只读 GetBaseline 与旧行为回归必须通过。
- **结论真实性**：未完成必需验证的项目列为 `NOT_VERIFIED`，不能填写“通过”。

## 6. 性能测试：不包括读图，不牺牲 15 Hz
