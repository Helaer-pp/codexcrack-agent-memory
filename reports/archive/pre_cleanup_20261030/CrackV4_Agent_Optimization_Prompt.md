# CrackV4 传统视觉裂纹检测算法优化任务书（给代码 Agent 的执行 Prompt）

> **角色定位**：你是一名资深 C++17 / OpenCV 机器视觉与实时算法工程师，负责在现有 CrackV4 代码上完成**可验证、可回退、可测量**的增量优化。你需要实际阅读、修改、编译、测试项目，而不是只输出一份概念性建议。
>
> **任务原则**：正确性和误检控制优先；保留已验证效果；性能以目标硬件实测为准；以有限改动增强鲁棒性，不追求不受约束的“万能检测”。

## 0. 工作材料与已知前提

优先阅读以下现有文件及其调用关系：

- `CrackV4.cpp`：`Detector`、配准、seed、tile、DP ridge、入口/根部、尖端、时序、C API。
- `CrackV4.h`：对外 C ABI、图像及结果结构体。
- `CrackV4.hpp`：C++ OpenCV RAII 封装。
- `scipy_gaussian_kernels.h`：用于兼容 SciPy 的高斯核。

**已经确定的约束（不得违背）：**

1. **只处理像素空间结果**：输出裂纹尖端 `(x,y)`、根部 `(x,y)`、中心线、跟踪路径像素弧长、根部到尖端的像素长度及有效性状态。真实单位换算由算法外部完成；不要在本任务内研究、训练或优化 `mm_per_pixel`。
2. **不使用神经网络/深度学习**：不引入 Torch、ONNX 推理或额外的大模型依赖。主体保持 C++17 + OpenCV 传统视觉算法。
3. **实时要求至少 15 Hz**：完整单帧处理周期必须能够适配 **66.7 ms/帧**。在明确相机采集、复制、显示等开销之后，再为算法分配预算；可暂以算法 P95 **45–50 ms** 作为初始工程参考目标，**不得把它当成已验证指标**。
4. **只有四组真实裂纹试验图像，且原 V4 已经验证通过**。把它们当作不可退化的回归基线。不得假称存在更多标注或据此声称已证明跨材料泛化。
5. 主任务仍是**已知参考图、参考定位点、单条主要裂纹的时序检测/跟踪和测量**；不要求任意场景全图多裂纹发现，不默认要求分叉裂纹的完整拓扑解析。
6. **保持已有公开接口可用**。不能静默破坏 DLL C ABI、`struct_size` 校验、调用者的对象生命周期和已有业务结果字段；如需扩展接口，优先设计显式 `V2`/版本化接口或向后兼容适配器。
7. 避免“为新算法而新算法”：应先复现实验、找出失败模式，再实施必要改动。任何对 V4 结果有影响的改变都应可开关、可对照、可回退。

## 1. 总体目标与成功定义

在不推翻 V4 主框架的前提下，按照下述顺序改进：

- **可靠性**：分清“找到一条路径”“跟踪停止”“尖端可信”“完整像素长度可信”；弱证据输出不确定，避免将信号消失直接等同于物理尖端。
- **精度**：现有四组试验不发生无根据的漏检、误检或尖端定位、路径长度退化；重要异常情况有明确状态输出。
- **时序**：路径前缀重复不能单独作为新尖端已确认的证据；裂纹生长时允许尖端合理前移。
- **速度**：正常帧维持快速路径；新增的末端验证优先复用已有 tile/DP 响应；复杂回退只能低置信度触发，且有硬性次数/时间预算。
- **鲁棒性**：在有证据表明值得实施时，逐步改进亮度、对比度、局部宽度、有限转向等扰动适应能力。

**不允许**用“全部改成更保守的未确认”来降低误报，然后宣称精度提升。必须同步报告召回/漏检、误报、确认延迟、未确定比例以及像素坐标/长度误差。

## 3. 阶段 A：零/低额外开销的正确性和状态修复（第一批提交）

### A1. 修复只读基线查询的副作用

检查 `CrackV4GetBaseline()`：当前未缓存 baseline 时可能再次调用 `process(reference, nullptr, true)`；该调用可能触发不必要的自动配准，还可能在部分路径上更新检测 history。

- 调整为**只读缓存返回**，或使用彻底独立的临时检测上下文进行参考图分析。
- 对 reference→reference 路径，若确实需要配准，应是 identity，而非要求纹理 patch 成功配准。
- 通过单元测试证明：读取基线前后，同一图像序列的时序输出一致；重复查询不改变 `history`、`previous`、配准状态。

### A2. 处理 `reference_mode=Auto` 的不确定基线

检查初始化中 `mode==2`：当参考图已有弱裂纹而 absolute 检测不完整时，不能悄悄视作“已确认干净”。

- 至少建立内部参考状态 `Clean / Cracked / Uncertain`，并写清每种状态的证据与含义。
- 初次提交可只做**诊断/记录**，默认不改变四组已通过数据的行为。
- 对 `Uncertain` 的保守处理或基线补充搜索必须经过单独回归验证后再开启。
- 核查 `baseline_path = b.prior.empty() ? b.path : b.path;` 的真实意图；仅在确认语义后修复，不要猜测。

### A3. 区分历史路径与历史尖端证据

当前 `history` 保存 `Path`；路径前缀匹配更多验证“同一条裂纹”，不能独立证明“同一真实尖端”。

- 将历史观测扩展为 `Observation`（至少包含路径、跟踪末端、该帧末端是否可信、停止原因、帧序号/有效性）。
- 路径历史用于稳定 seed/路径关联；尖端证据用于尖端确认。两者不可互相替代。
- 保留单帧强证据确认通道，但必须有与所报告末端相关的有效证据。
- 弱证据候选允许处于 `pending/uncertain`，不要强行输出已确认的尖端。
- 保证逐流、顺序处理；提供必要的时序重置机制，防止换试件/重复使用 handle 时继承旧历史。

### A4. 像素接口与 ABI 兼容

- 内部算法与新的对外结果主要采用**像素单位**，例如 `tip_px`、`root_px`、`tracking_endpoint_px`、`observed_length_px`、`root_to_tip_length_px`、`tip_confirmed`、`length_confirmed`。
- `observed_length_px` 指实际跟踪路径的像素弧长（可存在短间隙桥接，不能宣传为严格逐像素真实可见长度）；完整长度必须明确其根部补全/推断部分。
- **不要直接删除旧 C ABI 的 `length_mm`、`mm_per_pixel` 字段以致破坏旧程序**。旧接口可保留兼容行为，但本任务的算法评估和新增接口不依赖毫米换算。
- 禁止把 `(0,0)` 当作唯一的失败指示；应配合 `*_confirmed` 等有效性字段。

### A5. 明确可见的遗留项

- 对 `Tile::raw`、`bounds`、临时 buffer 等字段逐一查引用；有确切证据证明未被读取的计算可删除。
- 保留数值兼容行为（包括 SciPy Gaussian 核、NumPy 类归约与 DP tie 顺序），除非差异经过显式测试且收益明确。

## 4. 阶段 B：提高尖端与整条路径的可信度（核心算法升级）

### B1. 跟踪终止 ≠ 真实裂纹尖端

当前 `process()` 基于 `stop == "evidence_ended"` 设置尖端候选；请先将“停止原因”与“尖端真实性判断”分成两个独立步骤。

设计一个轻量级 `validateTerminal(...)`，优先复用**末次 tracking tile 已有的 `score / valid / material` 和路径强度**，在必要时增加很小的原图 ROI 采样。至少评价：

1. 终点之前的若干像素是否存在连续、足够的裂纹证据；
2. 终点之后在允许的小角度范围内是否存在合理的继续路径；
3. 此区域是否因低对比度、无效 mask、近图像边界或配准不可信而无法可靠判断；
4. 局部延续搜索是否可能仅因为人为阈值偏高而失败。

返回结构化终端证据（例如 `verified / uncertain`、原因、基本质量指标），**不能仅因“前方无响应”就声称已确认物理尖端**。结合时序判断给出最终 `tip_confirmed`。

禁止新增每帧全图检测；禁止在未设置预算情况下进行无限前向/角度搜索。末端确认失败时可以保留 `tracking_endpoint_px`，但 `tip_confirmed=false`，完整长度状态应保持可信语义。

### B2. 计算整条路径与尾段质量

当前 `Quality` 的重要指标主要取自 seed 初始段，不能直接代表整个路径或末端质量。

在**现有 tile 跟踪循环内**额外累计少量统计信息，尽量不重复采样：

- `path_support_fraction` / 各 tile 支持比例；
- `tail_support_fraction`、尾部强度/形态；
- 最长连续低支持区间；
- 路径宽度突变、过度弯曲等异常标记；
- 配准质量与根部有效性标记。

决策上区分：`seed_valid`、`path_valid`、`terminal_valid`、`root_valid`。不得仅凭 seed 峰值强就直接确认远端尖端。

### B3. 时序证据更新

- 默认保留 V4 的时间窗口和命中次数作为可比较基线参数，**不要先靠改阈值调出看似更好的结果**。
- 路径前缀相似主要用于裂纹身份关联；末端需要独立的当前帧证据。
- 允许符合实验工况的尖端沿中心线前移；不要强制“连续三帧尖端坐标不动”。
- 对短暂遮挡/模糊，优先给出“当前末端不可确认”，而不是缩短已知的历史裂纹。历史结果与当前观测应分别保留，禁止无证据直接复制旧尖端作为当前确认结果。
- 逐帧记录确认依据，便于定位误判来源。

### B4. 用影子模式对照，确认后再替换旧判定

新旧尖端判定先并行记录或通过 feature flag 切换：

- `legacy_tip_decision`；
- `new_tip_decision`；
- 每帧分歧原因与人工真值（如有）。

只有在不明显降低原有四组试验的召回、尖端精度和确认及时性的前提下，才默认启用新判断。不要用“全部标为不确定”来虚假优化误报。

## 5. 阶段 C：性能优化与 15 Hz 预算

先 profiling，后修改热点。优先考虑以下**风险较低**的措施：

1. 删除确认未被使用的 `Tile::raw` 复制和无用 `bounds` 计算；
2. 减少反复分配的 `cv::Mat`、`std::vector`，必要时使用每实例复用缓冲区（注意线程和跨帧状态）；
3. 仅在确实测得收益时改进参考侧缓存，且验证“先重采样再滤波”和其他重排算法是否会改变数值结果；
4. 终端检查优先用现有最后 tile，不重复运行完整 DP；
5. 如果 profiling 证明长裂纹每帧重新从 seed 跟踪是主要瓶颈，再设计可开关的 `FastTrack`：验证历史路径、从旧尖端附近延伸、异常回退完整 V4，并定期全路径复核。

**性能测量协议：**

- 使用目标机器、Release、固定编译选项与可重复的 OpenCV 线程设置；
- 分别统计四组序列的 warm-up 后逐帧 `P50/P95/P99/max` 与超预算帧数；
- 区分纯检测、C API 调用、以及真实端到端采集处理流水线；
- 同时报最大图像尺寸、最长路径、最大 tile 数、启用回退时的耗时；
- 若测试硬件、摄像头流水线或图像尚不可用，标记“未验证”，不得宣称已达到 15 Hz；
- 新增任何 fallback 必须有搜索次数/区域/耗时上限，超过预算时返回不确定并优雅退出。

## 6. 阶段 D：按需启用的鲁棒性增强（不要一开始全改）

原则：V4 正常高速路径继续运行；**只对低置信度或明确异常场景**启用补充策略。

### D1. 光照 / 灰度鲁棒性

当前存在 `100/110/140/165` 等绝对灰度相关门限，且主要通过 offset 补偿亮度变化。先量化这些条件在四组数据和合成扰动下的失效情况。

若确有收益，再增加局部稳健光度校正 `current ≈ a * reference + b`，使用稳定背景像素估计 `a,b`，避免把裂纹或反光计入背景；对差分 residual 做 MAD 或类似噪声归一化。**不默认对参考和当前图各自做强 CLAHE**，以免产生伪差异。新路径必须有对照测试和开关。

### D2. 裂纹宽度 / 黑帽尺度

保留已验证的 `1×5 / 1×9 / 1×13` 黑帽核作常规策略。仅当宽度不匹配或 seed 质量明显不足时，再尝试有限额外尺度；避免每帧全尺寸多尺度计算。注意 anchor 间距不一定等于成像后的裂纹像素宽度。

### D3. 局部转向 / 方向

当前 DP 每步横向允许 `[-2,2]`；对于 `gap_unresolved` 或含糊的 `evidence_ended`，可以设计次数有限的小角度局部补充搜索。**不要简单在运行中取反 `forward`**：初始方向关联了 root、seed、patch、缓存和入口几何；如需双向假设，必须保证几何状态一致。

### D4. 配准

默认保留现有锚点刚体变换 + patch 相位相关。仅当数据证明存在系统性旋转/倍率误差且 patch 空间分布可靠时，再研究估计 rigid/similarity 的回退；当前基于位移中位数的一致性筛选可能提前剔除真实旋转分量，不能未经重设计就直接套用 RANSAC。不要无条件升级为 affine/homography。

## 7. 测试集、评估指标与回归门槛

### 7.1 四组真实试验

- **保持按试件/试验组隔离统计**，不把相邻帧视为独立材料样本。
- 如有人工标注：报告尖端像素误差（P50/P95/最大值）、像素弧长误差、误报率、漏检率、首次确认延迟。
- 如无人工标注：至少记录 V4 vs 新版逐帧差异，抽取首段、中段、末段、弱信号、根部和停止异常帧进行人工核验；**一致不等于正确**。
- 报告 `confirmed / pending / uncertain / error` 的比例，防止通过大量拒绝来“提高精度”。

### 7.2 受控扰动

在四组已有图像上建立固定种子的可重复扰动：曝光、gamma、对比度、局部阴影、噪声、轻度失焦、平移、轻微旋转、锚点抖动、可控尺度变化。几何变换必须同步更新标注坐标/anchors；参考与当前同时变化、仅当前变化应作为不同测试场景。

记录每项扰动的 V4 / 新版效果和性能变化。**合成扰动只证明局部鲁棒性，不等于在未知材料上已验证跨域泛化。**

### 7.3 必须增加的工程单测

- `GetBaseline` 多次调用不改变后续时序结果；
- reference 对自身的身份变换不会因为没有纹理 patch 而失败；
- 初始化 `Auto` 在参考裂纹不确定时不错误标记“已确认干净”；
- `tip_confirmed=false` 时仍可正确表示跟踪终点但不输出有效真实尖端；
- `root_confirmed=false` 时完整像素长度无效或显式标记推断；
- 单帧强证据与多帧弱证据各自符合状态机预期；
- 长期运行无缓存累积、历史串流和显著内存增长；
- C ABI、`struct_size`、GRAY8 stride、空指针/异常路径仍兼容并正确返回错误。

**验收原则：**新功能未经数据证实，就保持默认关闭或只提供诊断；不要设置凭空产生的“必须误差小于 1 px”等验收值。若已有业务精度容差或人工真值，请使用它们作为最终阈值。

## 8. 必须采用的开发流程

1. **审查与基线**：阅读全部文件、理解状态变化、编译原版、跑现有四组（如可获取）、建立回归输出和 profiler。
2. **小步实施 A**：正确性/状态/接口修复；每一项独立提交并运行测试。
3. **影子模式实施 B**：增加终端验证与路径/时序统计；先只记录新旧判定分歧，必要时根据人工核验调试，再决定默认启用。
4. **性能实施 C**：基于 profile 删除无用工作和减少分配；只有在长路径成为实测瓶颈时才上 FastTrack。
5. **有限实施 D**：按四组真实图与扰动测试暴露出的最主要问题逐项引入，不同时叠加多种 fallback。
6. **每阶段回归**：精度、错误率、不确定比例、确认延迟、P95 和超预算帧比例均需对照。
7. **记录与交付**：每项变更要能回答“修复了什么、在哪个样本改善、是否引入退化、增加多少耗时、如何回退”。

如果工程复杂度过高，**优先交付可运行的 A+B 与完整测试工具**，不要为追求表面上的“所有阶段完成”而提交未验证的大规模重构。

## 9. 最终交付物

完成后至少提交：

1. 实际修改后的 C++ 源码与必要新增头文件，保留原 DLL/C++ 调用方式可用；
2. 功能开关、默认行为和回退机制说明；
3. 可执行或可复现的回归/扰动测试脚本或测试工程；
4. `reports/v4_baseline.md`：原版关键行为、已知问题和性能；
5. `reports/optimization_results.md`：修改项、前后对照、失败用例、准确性、15 Hz 性能、未验证事项；
6. 更新后的 README / API 文档，明确：像素输出、候选与确认状态、各种长度的语义；
7. 一份简短的变更清单，指出哪些优化**已验证默认开启**，哪些仅**实验性/默认关闭**。

最终汇报使用以下固定结构：

- **已完成并验证**：文件/函数/测试证据；
- **改进结果**：按四组试验分别给出坐标/长度与误报漏报变化；
- **速度结果**：目标机器、Release 配置、P50/P95/P99/max、是否达到至少 15 Hz；
- **兼容性**：对旧 API 和旧输出的影响；
- **仍有风险**：缺少真实样本、尚未覆盖的工况和未验证假设；
- **建议的下一步**：只列由实验数据支持的优先事项。
