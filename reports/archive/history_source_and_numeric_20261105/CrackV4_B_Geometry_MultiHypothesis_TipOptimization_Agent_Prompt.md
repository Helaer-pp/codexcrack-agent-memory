## 2. 要解决的技术问题与成功定义

### 问题 T1：错误长尾与错误分叉

A 有时从真实暗线延伸到静态纹理、孔缘、运动伪影或错误支路。需要回答：**第一次路径分歧/证据衰减发生在何处？它是分叉选择错误，还是同一主干上的错误继续延伸？** 不能默认终点前最后 20 px 才有问题。

### 问题 T2：真实弱裂纹的提前截短

真实裂纹可能由深变浅、局部断流、弯曲、闭合或改变方向。所有“早停止”“反证”“ROI 裁切”的候选，必须在已知真实渐浅/弯曲/短暗线场景中证明不会导致系统性误伤。

### 问题 T3：几何配准不确定引起的路径放大效应

P1/P2 初始位姿、参考/当前材质匹配、A 原生 refine 后的映射可能不一致。必须区分**真实可验证的材料变换**、**只是数值上稳定的候选**、**独立检验失败**。不能把 NCC 高值自动当成正确材料点对应，也不能声称仅靠两个点可恢复任意非刚性形变。

### 问题 T4：根部/ROI 自动生成与跨试件通用性

ROI 必须由**参考图及 P1/P2、可识别几何**按同一套规则产生；有条件可按图像证据扩展。禁止按数据集名称、帧号、已知结果、A 的路径末端或人工复制的试件坐标来确定 ROI。**ROI 只决定搜索空间，不代表物理终点。** 初始化无法判定则返回明确失败原因。

### 问题 T5：终点不可观测时如何诚实输出

将“当前图像可见暗线尖端”与“材料已形成物理裂纹尖端”分开。没有同步载荷/相位、独立材料跟踪或物理真值时，真实物理尖端精度必须标 `N/A`。允许 `UNKNOWN/AMBIGUOUS/NOT_OBSERVABLE` 的研究状态，但**不得通过大量拒绝正例来虚增准确率**。

### 3.1 B0：统一材料坐标与自动 ROI

实际实现并独立测试以下合同：

- 参考像素坐标、当前像素坐标、局部 ROI 坐标、材料主轴坐标和原图回投分别定义；所有路径点用 `float64` 储存，避免重复插值误差。单纯浮点回投不等于亚像素真精度。
- 初始运动采用 P1/P2 推得的受约束几何变换；先核实两点能支持什么运动模型。分别记录 P1/P2 观测质量、根部位置及协方差/容差来源。
- 参考图中识别孔/缺口/材料边缘的**通用算法**；可以识别几何类型决定单侧/双侧 ROI，但不能针对项目名称选参数。
- ROI 初始覆盖沿主裂纹扩展方向的合理韧带区域，并预留转向余量；扩展触发仅依赖当前可计算证据，避免漏掉弯线。对越界、错误根部、识别不确定必须明确状态。
- 自动 ROI 是否正确要单独用程序已知根部/路径及独立物理几何测试，而非用最终检出帧数代理。
- 对所有数据输出 `root_source`、`roi_geometry`、`roi_margin`、`root_confidence_type`、`out_of_roi_truth`（仅受控 GT 可用）及 `reason_code`。

**重要**：若 P1/P2 与参考图不足以唯一定位根部，不得偷偷读取旧硬编码参数。此时输出 `ROOT_UNIDENTIFIABLE`，并评估需要补充哪一种最少输入（独立材料标记、已知几何尺寸或物理标定）。

### 3.2 B1：几何可信度与材料独立证据

- 不修改 A 原生 refine；研究旁路至少比较 A 当前映射、P1/P2 刚体初值及在实际可独立验证时的材料匹配候选。
- 用**独立材料区域、负控制或合成已知变换**检验变换，而不是看 A/Frangi 输出是否一致。
- 对照区域需要排除真实裂纹、新开口、孔边与饱和/强反射；有效匹配像素、峰值歧义、局部残差和置信边界要逐帧记录。
- 旧研究曾显示部分材料缺乏可靠独立匹配。无有效对应时必须返回 `REGISTRATION_UNKNOWN`，不可硬补一个最高 NCC 方案。
- 使用预声明的局部有限扰动集合做敏感性研究；扰动是**诊断**不是物理真值，不以最稳定候选自动替换 A。
- 记录路径起点、分支、路径主体和终点对变换变化的敏感性，避免只报尖端距离。

### 3.3 B2：对 A 的整条路径进行分段证据审计

不改 A 输出，仅研究路径：

- 在固定步长和自适应细化位置采样沿线局部暗谷与两侧对比（必须明确轴向、法向及半径来源）；
- 把**原图局部暗线支持**、**可信条件下的参考变化**、**噪声/饱和/形态伪影**分开记录，不能混成一个“可靠概率”；
- 支持完整路径的分段指标：连续支持长度、连续不支持长度、可观察区间、支持恢复点、分叉点、结束前一段、末端；
- 输出从根部到端点的连续证据序列与关键断点，而不是一个平均分；
- 生成可复现的图层：原图、参考差分（仅诊断）、A 中心线、证据轨迹、敏感区间。正式视频仍只显示确认后的原路径与一个尖端。

**禁止**：固定“连续 N 个弱响应就截断”“在第一个失支持点截断”“以 A/Frangi 分歧点为真尖端”。这些只能是候选生成假设，必须在受控弱线/渐浅/断线/闭合案例上验证。

### 3.4 B3：显式的少量路径与停止假设

对一帧最多维护少量（初始建议 `K≤3`，实际 K 在 DEV 固定）结构化候选：

- `H_A`：冻结 A 原路径和端点（默认保留）。
- `H_SHORT`：同一主体路径上更早停止的候选；必须有可检验的局部终端证据，不得只裁掉末尾。
- `H_ALT`：真实存在高竞争得分时从分歧点产生的备选分支；没有高竞争分支就不得编造。
- `H_EXTEND`：仅在已知渐浅/提早停止问题且存在受支持延伸候选时研究；不得无约束继续追踪。

实现上优先基于现有 DP tile / seed / 路径打分的**只读候选导出或独立复刻**；如果必须在生产 C++ 内插桩，使用严格的研究副本，禁止改冻结库文件。记录每个候选的父分支、停止位置、原始路径得分、证据可评价性和耗时。不要一开始就引入复杂的全局图搜索或深度学习。

建议先只实现 `H_A` 与 `H_SHORT` 的独立分析，再看是否有证据值得加入 `H_ALT`，避免为了复杂度而复杂度。

### 3.5 B4：D+G 退回**有条件的局部证据**，不再充当硬门控

使用三态，不是通过/失败二元化：

- `SUPPORTED`：在配准与光度条件已验证可评价的局部路段存在支持。
- `CONTRADICTED`：有独立可检验的反证；**定义必须由 DEV 与阴性控制实验验证**。
- `UNKNOWN`：参考错位、孔缘、曝光、闭合、弱暗线或其他条件不满足。

如果不能证明 `CONTRADICTED` 的判别能力，则只保留 `SUPPORTED/UNKNOWN` 的描述性输出，**禁止让它修改尖端**。

严格禁止：

```python
confirmed = A.confirmed and DG.confirmed
if not DG_support: truncate_A()
if Frangi_tip < A_tip: replace_tip(Frangi_tip)
```

不使用大尺度形态学闭运算作为直接接续路径依据；此前 `false_bridge` 与 `hole_motion` 反例须持续保留为必测场景。

### 3.6 B5：候选决策与可校准的不确定性

决策研究必须与候选生成分开消融。初始设计应**优先回退到原 A**；只有预注册实验表明某一类可辨认错误确实能够被区分，才允许对该类型做有限修改。

研究输出：

- `KEEP_A`：保留冻结 A 输出。
- `CORRECT_TIP`：候选端点有充分独立受控证据支持；单条路径、单个尖端；记录修正幅度。
- `AMBIGUOUS`：多个候选无法区分；研究结果记录，不等同于成功测量。
- `NOT_OBSERVABLE`：当前证据不足；记录不可观测原因。
- `NO_CRACK_CONFIRMED`：仅当阴性证据确实支持时使用；不能把未知当无裂纹。

应分别给出**研究模式的建议状态**和**生产 A 原始状态**；研究状态不能污染 A 的历史缓存与视频。不得宣称未校准的分数是物理真值概率。

## 5. 验证指标：禁止用一个 MAE 或“确认数量”掩盖损失

所有下列指标必须按**相同受控案例和 side 的配对**输出，既保留帧级记录，也用**案例聚类**计算不确定区间；相邻帧不可当作独立试件。不同背景/场景分别报告。

### 5.1 正例与阴性、错误尾部

- 总正例/可观察正例/已形成但不可观察正例/阴性分母；失败/拒绝/未知/正式确认计数；
- 正例确认覆盖率、FN、阴性误确认率 FP、受保护原 A 正确确认的保留率；
- **原 A ≤8px 正例被候选撤销多少**，原 A 已正确尖端被误改多少；
- 条件尖端二维 MAE、MedAE、P95、P99、最大值、`>8px` 尾部计数；
- 有序中心线弧长误差与主轴投影误差**分开**报告；
- 错误延伸（过长）与提前截断（过短）数量及幅度，路径主体偏离、错误分叉、根部错误；
- 允许 `UNKNOWN` 时必须计入覆盖率代价，另做“确认-风险曲线”，不得只报告剩余确认样本条件 MAE。

### 5.2 最低准入门槛（在 TEST 前固定为机器可判定的数值）

采用**联合门槛**，不可只在一个场景显著改善就发布：

1. 新 TEST 上正例确认覆盖不得明显低于 A；应预注册非劣容限及置信界。为避免“大量拒绝提高准确率”，初始建议绝对覆盖下降容限不超过 **0.5 个百分点**，若样本量不足以判断，则 `INCONCLUSIVE`，不可自动放宽。
2. 阴性误确认数量及率**不能高于 A**，并报告配对置信区间；如未有充分统计能力证明非劣，标记 `NOT_PROVEN`。
3. 受保护的 A 正确确认（如 `tip_error ≤8px`）不得出现系统性撤销或错误改尖端；**必须报告绝对损失和比例，不允许再出现上一轮 1527 类大规模损失**。具体可接受上限要在 DEV 注册，不能 TEST 后修改。
4. 预注册的假尾/假分支场景必须在**实际尖端误差、尾部事件**方面改善，而非仅将这些帧改成不确认；同样不能明显加重渐浅、弯曲、孔缘、闭合等子组的错误。
5. 主结果优先使用**相同案例/帧对照的配对误差**及案例级 bootstrap 区间；对于跨场景改善，报告各背景区间，不能把 pooled 改善表述为所有材料均显著。
6. 若选择改变已有正确 A 尖端，必须单独证明该更改的可靠性。只读 Shadow 的输出零变化只能表明兼容，不等于精度提升。
7. 无独立真实物理尖端真值时，真实绝对准确率一律 `N/A`；成功仅能表述为“受控程序已知几何的性能改善”。

**推荐决策顺序**：真实性/统计可辨识性 → A 正例保留 → 阴性安全 → 尖端与路径误差 → 跨组表现 → 时延。任何硬门槛失败都 `KEEP_A`，不得用平均指标抵消。

## 6. 性能与生产工程门禁

目标部署约束：**C++17 / OpenCV 4.4 / 15 Hz，单帧完整原生核心预算 66.67 ms**。基于最新一次报告，A max 约 51.36 ms，但其他历史测试排除组X曾达约 61.58 ms；不同机器/环境不能直接比较。故研究中应优先复用 A 已计算的局部特征，限制额外全图卷积和多次重跑 DP。

- DEV 初期可用 Python 快速研究；**Python 耗时不等于 C++ 生产速度**。

- 统计 `Process + GetResultV2 + CopyPath + 必要分配/状态更新` 的**每帧完整核心耗时**，报告各试件 P50/P95/P99/Max/超预算帧数；测试同机、同配置、预解码输入、独占运行和运行环境。
- 完整核心每一帧 `Max ≤ 66.67 ms` 才能称此次受控测试达到预算；同时注明操作系统调度、解码、传输和显示链路尚不代表硬实时保证。
- 另检查 RAM 峰值、状态增长、输入非法处理、不同帧大小、P1/P2 有效性、未确认输出、单侧/双侧模式、参考重置、结果 buffer 容量、ABI 兼容。

- 若候选导致回归非预期撤销、ABI 不兼容或任一核心帧超预算：**不得发布新 DLL**。
