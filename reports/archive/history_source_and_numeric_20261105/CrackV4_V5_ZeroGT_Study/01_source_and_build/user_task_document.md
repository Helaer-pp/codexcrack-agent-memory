> **执行对象**：具备本地 C++17 / OpenCV 4.4.0 工程、原始数据、逐帧双基准点、构建与测试权限的代码 Agent（Codex / Claude Code / Cursor 等）。
>
> **任务性质**：实际修改、编译、运行、比较、交付。**不是只给研究建议、伪代码、截图或模拟日志。**
>

## 2. 本轮待验证的研究假设（必须能证伪）

### H1：Frangi 是否提供独立且实用的增益？

- 基于原图像局部灰度计算 **黑色细线的多尺度 2D Frangi vesselness**；注意特征值排序、暗脊极性、尺度归一化、近零响应、防止 NaN/Inf 和图像边缘。
- Frangi 与现有 Hessian/Steger、blackhat 高度共享线形态信息，**默认只是一个候选特征，不是裂纹身份判定器**。
- 必须比较 **单黑帽、单 Frangi、黑帽+Frangi** 在真实裂纹样式、背景线条、静态划痕、孔边缘以及程序合成的已知裂纹上产生的响应分布与误追踪。若只是把错误划痕响应抬高，否决 Frangi。
- 首选 **裁剪后的 ROI / 末端局部窗口**，禁止未经测速直接在整幅 5K 图上跑多尺度 Frangi。先少量尺度，按像素估计线宽自动选择、保留 sigma 与计算时间诊断；禁止为某组手工固化特定尺度。
- Frangi 只允许经实验确认后用于弱线候选生成或可信路径附近的亚像素定位，**不得独立赋予 `tip_confirmed=true`**。

### H2：参考帧变化与自适应背景模型是否比多加一个线性滤波器更有用？

- 使用双点建立基础几何变换，并核对在当前像素坐标系与参考坐标系间的映射；区分刚体对齐、局部变形和图像细化误差，不能在错误对齐下把差分直接当新裂纹。
- 在局部相邻背景上进行鲁棒亮度归一化（例如 offset / gain 或局部中位数方法），计算**有符号的新生变暗证据**，并记录光照大幅变化、过曝和信息不可恢复标志。
- 对 `crack-like response` 使用有效背景区域的鲁棒中心/MAD 标准化，负样本应来自相近材料、亮度、ROI 且排除孔边缘与已知裂纹走廊；背景不可得时输出 `BACKGROUND_UNRELIABLE`，不假造高置信度。
- 参考图已存在裂纹时，旧裂纹段可借助可信历史保留；不能要求整条裂纹在每帧都表现为新增变化。只对前沿新增段重点检测 `new-growth`。
- 将 `reference change`、`current line morphology`、`background-relative significance` 和 `temporal material-coordinate persistence` 分开记录，禁止把同源的黑帽/Hessian/Frangi简单加权就称多重独立验证。

### H3：显式停止状态能否在不大量误拒绝的条件下避免错误长尾？

- 保留已有 DP 主跟踪，但将候选状态至少扩展为：`CRACK_CONTINUE`、`SHORT_GAP`、`STOP`、`BACKGROUND/NO_CRACK`。
- 路径扩张得分必须对背景机会水平作比较，不允许继续依靠简单的非负响应累加把纹理拖出长尾；设计有界搜索、可解释的停止成本与单调性/转角软约束，避免“绝不允许向下转弯”等硬编码。
- **STOP 是路径推断结果，不是物理尖端真值**。候选 Stop 区域仍需局部支持与短间隙后延续检查；不能将搜索耗尽处直接设为有效尖端。
- 通过具有相同搜索预算/方向空间的背景对照路径估计 winner's curse（多路径取最大值产生的虚假高分），防止复杂背景在高自由度搜索下“必定找到一条线”。
- 只对证据不足的长尾拒绝，不应直接撤销完整已有有效前段；若无法证明物理尖端，内部提供 supported-prefix、对外 `full_length_valid=false`，并准确呈现无效状态。

### H4：有限候选和局部分歧恢复是否真能纠正早期路径选错？

- 只有在候选分支分数接近或局部质量分歧时才激活最多 `K=2~3` 条分支（可根据耗时上限自适应降低），不要全图重复搜索。
- 从**路径首次持续证据分歧区段**触发局部重搜索，不能只围绕已经离真实裂纹很远的错误终点重定位。
- 区分修正“中心线偏差”和“物理尖端终止”；仅在可信裂纹段做亚像素细化，末端证据不足时不得外推。
- 若原四组或合成实验没有可量化收益，必须移除/禁用无收益模块，而非叠加更多复杂度。

### H5：自适应阈值和时序是否能在新项目无标注的情况下稳定工作？

- 默认不需要用户提交裂纹真值，不需要项目级手工阈值。允许从参考帧和初始序列中估计背景分布，但不得假定所有初期帧都一定没有裂纹。
- 分开管理“测量可信历史”和“未确认搜索候选历史”；未确认长尾不得成为下一帧正式生长先验。
- 对同一材料坐标建立时间连续性检查，允许短暂裂纹闭合/亮度损失，不强制长度逐帧严格增加来掩盖假阳性；历史保持不等于本帧新测量有效，显示应以本帧状态为准。

## 4. 不需要人工真值的评价体系（严禁偷换定义）

### 4.1 真实试验数据：只统计真正可观测的指标

- `confirmed_tip_count`、`full_length_valid_count`、`supported_prefix_only_count`、`unconfirmed_count`、首次确认 `frame_id`、各组状态转移；注意数量变化不是准确率变化。
- 同一帧不同版本的尖端坐标差、路径弧长差、路径间距离、首次显著分歧位置、长度异常跳变与邻帧尖端异常跳变；这些都是**分歧/稳定性代理指标**，不是对真实尖端的误差。
- 参考图新增证据支持率、局部线形态和背景对照分位数、STOP 前后净证据、伪长尾长度代理指标；清楚标注这些指标具有模型依赖，不能用它们单独判定物理正确。
- 无裂纹/背景负对照：可使用参考帧、历史稳定背景位置与有明确注入方案的空路径 ROI；**不能把未标注的整批早期真实帧自动视为可靠无裂纹真值**。
- 反事实稳定性：对同一原图施加已知小尺度亮度、噪声、几何变换并逆变换回原图坐标，比较尖端与路径变化；另检验配准误差注入、饱和、遮挡、裂纹闭合和短间隙情况。真实精度依然 `N/A`。
- 逐组列出“新增已确认 / 失去已确认 / 尖端变化大 / 后缀截断 / 原始明显异常未解决”的帧号列表及可打开的原图、效果图；至少避免旧实验那类 **336 帧净确认损失却缺少撤销归因** 的情况再次发生。

### 4.2 合成与半合成：允许给出已知真值误差

- 从不同真实背景/参考图的小 ROI 构建程序化的暗裂纹注入，生成**已知根部、中心线、真实尖端、宽度和长度**的完整序列，覆盖弯曲、分叉、短间隙、逐渐变浅、固定划痕、颗粒背景、低对比度、阴影、过曝、几何偏移及长尾诱导纹理。
- 必须包括“有清晰前段、后面有很强但不属于裂纹的暗纹”的极难负例；以及“中间弱、后端仍是真裂纹”的反例。
- 只在**程序合成 GT**上报告 tip MAE/P50/P95/Max、中心线距离、长度误差、假确认、漏确认和无裂纹误报；独立生成开发与测试随机种子/背景切片，防止用相同注入模板选参数又测试。
- 模拟图与真实图单独统计，禁止把合成准确率写作真实材料准确率。
- 如果某类合成不符合真实成像特征，应明确指出外部效度限制。

### 4.3 冻结后的第五组

- 以冻结 commit + config + SHA256 执行**一次完整序列**，不根据结果修改本轮参数。
- 必须列出 `frame_id=51`、`frame_id=473` 的原图、算法最终叠加图、完整实际测量字段、路径支持证据、与稳定版/研究版的区别。不能只返回“未确认”就宣称真正找到了尖端，也不能只返回漂亮的线条就宣称正确。
- 已知故障回归是**已知挑战**，不是完全盲测；其它第五组帧只报告无真值稳定性与可见异常的客观信息。
- 若发现问题，记录为 `NEXT_CYCLE_FINDING`，保持当前冻结版及结果不变，后续新研发周期再使用新外部数据验证。

## 5. 输出视频的**强制简洁渲染规范**（本轮最高优先级 UI 验收）

**用户要求：最终 MP4 上只显示算法本帧真正认定有效的裂纹尖端位置和从根部到该尖端的实际中心线路径，不要多余的绿色线条、虚线或辅助可视化。此条违反即判交付不合格。**

### 5.1 最终效果视频画什么

1. 底图：**未美化的真实原始试验帧**，保持纵横比和正确的原图坐标映射，不得用模型输出替换底图。
2. **仅当 `tip_confirmed == true` 且 `full_length_valid == true`，并且路径几何自洽时**，绘制**一条实心、连续、细线**（推荐高对比橙红色，约 2 px，尺寸按输出分辨率适配）：由实际根部沿最终算法中心线到实际已确认尖端，**不能继续画过尖端的搜索尾部**。
3. 在该路径最后一个点只绘制 **一个小的实心圆点**，表示**本帧算法最终确认的尖端**；圆点必须与折线路径最后点及对外坐标一致。
4. 允许用紧凑的小字体显示 `Tip=(x,y)`、`Length=... px`，字体放在画面边缘/小的非遮挡区域；数值必须来自本帧正式算法结果。若遮挡关键细节则不要显示文字，逐帧 CSV 仍保存准确值。
5. 对**未确认/不完整**的帧，最终视频只显示原始图像（可以在画面边缘显示极小的 `UNCONFIRMED` 文本，也可不显示），**不画候选中心线、不画候选尖端、不画上一帧尖端、不画部分路径冒充已确认测量**。受支持但末端不确定的路径仅写入调试 CSV/专用诊断图，不进入最终视频。
6. 全帧仅使用同一种路径颜色和一个末端点颜色；对不同算法的**并排对比视频**，左右面板分别只绘制各自的单条有效路径与尖端，不在同一原图中画两条叠加，也不得在其上加差异箭头。

### 5.2 最终效果视频禁止出现

- 禁止为了视频清晰度手动移动尖端、重新绘制理想路径或用时序平滑后的假坐标覆盖 DLL 当前输出；如未来确有在线时序算法，应让**实际 DLL 正式输出该结果**，CSV 和视频一致。

### 5.3 视频与数值一一对应（必须写自动测试）

- 用同一个正式输出对象生成 JSON/CSV 与渲染标记；导出原图像素坐标，检查根部、中心线各点、末端点、像素弧长一致，且渲染坐标变换可逆。
- 对所有有效帧：`rendered_tip == final_path.back()` 在原始像素坐标下误差小于数值/取整允许的极小容差；`rendered_path` 不得超出有效长度终点；`full_length_px` 来自该正式路径的弧长或已有明确定义的长度逻辑（不得画一条线却报告另一条路径的长度）。
- 对所有无效帧：自动抽样或逐帧判定没有有效路径、尖端的叠加；且仍保留原图和正确 `frame_id`。
- 禁止通过绘制库自动叠加上一帧状态形成拖尾。MP4 生成后必须解码检查帧数、顺序、尺寸、帧率、文件大小与 SHA256。

## 7. C++ / DLL / 工程约束

- 工程以 C++17、现有 OpenCV（此前为 4.4.0）为基础；保留现有稳定版 ABI、导出函数、结构体布局、`CreateExtended`、`Process` 逐帧基准点及 `GetResultV2` 行为。新字段通过版本化扩展接口、可选诊断输出或旁路 CSV，不破坏老用户调用。
- 每帧实际的 P1/P2 为高优先级几何输入，若无效必须返回明确错误/不确定状态，不得静默切换到已有成功误配风险的自动模式仍认定高可信度。
- 先测真实 ROI、过滤尺度与分配热点；缓存高斯核/临时矩阵，避免反复全幅分配；不得在最坏帧进行无界候选扩张。
- **完整 `Process` 算法计算**按预解码图像计时，包含实际调用中新算法及其内部必要变换、数据组织与历史处理，不计源图读取/解码、视频编码、报告生成和离线纯诊断（纯诊断不得影响正式数据和性能）。明确测试是否预热、线程数、机器、版本、编译选项、运行次数，报告 P50/P95/P99/Max 和超过 66.67 ms 帧列表。
- **任一正式测试帧 >66.67 ms，则不能宣称满足当前 15 Hz 单帧预算**；记录超时位置和热点，提供被动性能保护/计算预算与降级方案，但不能通过将复杂帧静默跳过或输出旧帧冒充新测量来“达标”。
- 单测：短路径、曲线末端、亚像素坐标、无效帧、mask、ROI 边界、参考图已有暗纹、极弱裂纹、灰度饱和、NaN/Inf、两点次序、时序 reset、并发安全、兼容 ABI、确认路径和实际尖端一一对应。

## 8. 如何判断是否值得发布（先定义，再运行）

分三层评审；任一版本都可能失败并回滚：

**研究层（可行性）**：Frangi 的特征收益是否独立存在？背景竞争和 STOP 是否改善合成 GT 的长尾误差/假确认？原四组的路径分歧是否减少、极弱裂纹是否仍可追踪？这些指标是否同时满足而非只减少确认数？

**工程层（候选准入）**：所有 DEV 四组完整回归跑通，无状态/接口违规，无明显跨组重大退化，算法运行全部符合 66.67 ms 预算；`videos/final/` 无任何多余绿色/虚线/候选图，CSV-视频坐标一致，文件真实可解码。

**发布层（实际产品风险）**：真实数据没有独立尖端 GT，不能证明绝对精度；如果仍出现明显错误长尾或明显无裂纹假确认、弱裂纹大量丢失、性能超时，则标记 `NOT_RELEASE_READY`。即使所有无真值代理测试都通过，也应如实标明真实精度未知及未知工况风险，不作无依据的“高普适性/亚像素真实误差保证”。

不得以“确认总数增加”替代真实改善，也不得以“确认总数下降”冒充误报已消除。逐版本展示 **新确认、失去确认、变化原因、无新增证据长尾案例、弱裂纹疑似漏检、算法耗时**。
