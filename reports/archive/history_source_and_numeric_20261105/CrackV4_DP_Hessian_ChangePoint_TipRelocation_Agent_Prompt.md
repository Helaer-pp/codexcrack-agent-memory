# CrackV4 下一代局部证据与尖端定位优化：代码 Agent 执行任务书

> **任务类型**：在现有 C++17 / OpenCV CrackV4 上进行可回退、可量化、可复现的算法研发与交付。  
> **技术路线**：**保留现有 DP 主跟踪 + Steger/Hessian 亚像素局部验证 + 沿路径的鲁棒变化点分析 + 有界末端重定位**。  
> **数据隔离硬规则**：**原四组试验只作为开发/调试/内部验证数据；第五组排除组X试验只在所有代码、阈值、配置和验收流程冻结后，进行一次性最终验证。**  
> **优先目标**：同时降低错误长尾及伪尖端、恢复明显真实裂纹的正确尖端与完整像素长度；**不能靠简单撤销大量确认来宣称成功**。  
> **非目标**：神经网络、毫米标定、整图重构、全图高成本搜索、为了演示效果手工逐帧改结果。

## 1. 项目背景与已知基线

现有系统输入参考 GRAY8 图、参考双基准点、当前 GRAY8 图与可选当前双基准点；输出当前可见裂纹路径、跟踪终点、已确认物理尖端与像素弧长及各自有效位。主算法是参考差分/黑帽/局部 seed/tile/动态规划 (DP) 跟踪与时序确认。试件以**已知孔边缘起始的单条主裂纹**为主要范围；既可能参考图无裂纹，也可能参考图已有裂纹。允许裂纹闭合或姿态变化引起可见长度缩短，不强加单调长度先验。

### 本轮要解决的本质问题

1. 找出 DP 候选路径中**哪一段确实有持续的、符合裂纹形态的证据**，哪一段只是背景纹理、阴影、配准残差或累计分数带来的“可连通伪延伸”。
2. **末端附近出现弱信号/短间隙时，不可直接认定裂纹结束**；要在有限 ROI 内判断能否重新连接真实裂纹。
3. **“最后可见支持点”与“物理裂纹尖端”必须分开**。截断候选路径不自动生成物理尖端真值；证据确实充分时才确认完整长度。
4. 不能通过大幅降低旧版确认数量来换取更少的假尖端。应提高“正确确认的精度和覆盖”，而不是“拒绝率”。

## 4. 必做阶段 B：Steger/Hessian 局部线状证据

在**已有 DP 路径周围的窄带 ROI** 内计算，不得全图扫描。实现亚像素级的细暗线方向与中心定位，至少支持 1–2 个有界尺度，是否增加第三尺度必须通过 DEV-4 消融和耗时证明。

### 4.1 技术内容

- 在正确的灰度符号约定下计算局部 Gaussian 一、二阶导数及 Hessian 的特征值/特征向量，提取代表暗线法向的二阶响应。方向符号、亮暗反转必须通过合成样例测试。
- 沿 Hessian 法向估计亚像素横向偏移，例如用局部二次模型 `t = -(∇I·n)/(nᵀHn)`；只在曲率稳定、分母非零、偏移处于采样像素邻域等有效条件下输出中心候选。
- 记录 `ridge_response`、`ridge_orientation`、`subpixel_offset`、`ridge_valid`、方向与 DP 切向相容性，不得仅凭 Hessian 强度就认定是真裂纹；划痕、材料纹路也可能具备同样特征。
- 对候选路径每若干像素采样横截面：中心暗谷深度、两侧亮度差、可解释的裂纹宽度/连续性、动态背景噪声尺度。适当使用局部 median/MAD 标准化，不以材料绝对灰度或固定宽度一票否决。
- **区分当前帧“有裂纹样线状结构”与“参考图不存在的新增裂纹证据”**：对于参考帧已有裂纹，允许当前路径与参考路径重合；新增性只应用于可判定为新生/扩展的部分，避免把 precracked 参考错误拒绝。
- 正确处理饱和、模糊、图像边缘、ROI 越界和配准不确定。这些情况下证据可以标记 `unavailable`，不能自动等同于 `no_crack`。
- 不允许亚像素中心纠正使输出脱离原始像素坐标系；测量长度定义必须明确是原 DP 离散折线弧长还是新亚像素折线弧长，输出必须有版本说明且相同口径比较。

### 4.2 必须通过的独立单元测试

- 合成直线、倾斜直线、圆弧暗线、不同亚像素平移与线宽：记录中心点偏差、方向偏差、丢失率。
- 平坦背景、颗粒纹理、孔边缘、非裂纹划痕：不得因 Hessian 线响应单独确认为物理尖端。
- 低对比度短线段、部分饱和、短间隙与高曲率：证明边界状态可区分“没有证据”和“证据未知”。
- 对比不同尺度与局部归一化的独立收益；避免在 DEV-4 中为单组调整大量特例常数。

**阶段 B 交付**：`ridge_evidence` 可独立关闭；`tests/test_ridge_evidence.*`；四组局部证据曲线及原图 ROI 图例；不允许默认否决旧结果。

## 5. 必做阶段 C：沿路径鲁棒变化点检测

### 5.1 核心设计

将现有 DP 路径用原图像素弧长参数化为 `s=0..L`，以小步长采集多通道证据：

- Hessian/Steger 线状支持、横截面暗谷及宽度连续性；
- 在配准可信情况下的参考-当前对比（含光照/饱和质量标志）；
- 路径局部切向、转角/曲率与线方向一致性；
- `missing_evidence / unavailable_evidence` 的不同原因；
- 有效路径支持与可疑延伸的连续距离，而不是整个路径平均置信度。

以鲁棒的局部窗口统计建立 `supported / weak / unsupported / unavailable` 四态证据序列。支持度阈值需从 DEV-4 数据、合成场景和独立 GT 选择，不得简单固定为某个全局灰度阈值。

变化点检测至少尝试并对比：

1. 滑动窗口鲁棒统计 + 双阈值滞回及最小持续长度；
2. 有界的 CUSUM/局部变点得分（或等效小开销方法）；
3. 对原 DP 累计分数与新增独立证据分开分析，不得将同一证据重复加权伪装为“独立确认”。

**关键约束**：变化点是“路径可能失去支持的位置”，**不是自动的物理尖端**。短暂弱响应允许在局部有强证据重新连接；连续有结构的真实弯曲裂纹不能仅因角度变化被截断。不要把整个帧的确认状态直接由单一变化点阈值决定。

### 5.2 诊断与消融

对每个候选输出：

`last_strong_support_s`、`first_sustained_loss_s`、`change_point_s`、`weak_gap_px`、`unsupported_tail_px`、`evidence_availability`、`change_point_reason`。

形成四组 DEV-4 的沿路一维证据图与对应原图标注，尤其核查真实裂纹长、细、弯、浅的部分。不允许为了“所有假尾都截掉”造成大规模完整长度确认下降。

## 6. 必做阶段 D：有界末端重定位（只在争议区域触发）

### 6.1 触发条件

当末段证据持续下降、DP 末端存在明显弱长尾、局部线方向与路径方向偏差、连续弱信号后重新出现强证据，或终端审计与 DP 冲突时，才启动**有界局部重定位**。正常强证据帧不重复搜索。

### 6.2 搜索与裁决

- 以变化点前后的小 ROI 为中心，使用局部原图和参考图；允许少量（例如 2–4 条）由 Hessian 线方向引导的短候选/短 DP 或局部图搜索，探索短间隙后真实裂纹的可能续接。
- 所有窗口半径、最大路径长、最多分支数、最大回退次数、最大迭代数必须有配置上限；先按 15 Hz 预算做剖析，再按 DEV-4 选择最终边界，不能无界扩张。
- 候选选择既考虑独立局部线状/暗谷/新生证据，也考虑平滑连通与起始路径约束；**显著转向本身不能自动拒绝**，但弱证据且大转向须有额外支持。
- 若发现可靠的真实延续，允许越过短弱间隙继续跟踪；若找到可信终点，输出其亚像素坐标和完整弧长；若只确认可见末段而没有物理尖端证据，应输出有效可见路径、`tip_valid=false`、`complete_length_valid=false`，并记录原因。
- 原 DP 路径、保留有证据的路径、最终被确认的测量路径分别存储；**不能用无证据的路径尾部累加完整像素长度**。重定位不可凭空跨越大段无证据空白。
- 不得强制长度单调增长，不得以历史已确认尖端代替本帧测量；历史只可提供合理的先验/审核信息。
- 当所有局部候选都失败时，明确标为 `TIP_UNCERTAIN` 或 `VISIBILITY_UNCERTAIN`，不能暗中回填旧位置或把变化点自动确认为物理尖端。

### 6.3 防止 v3 退化的硬要求

不要把“审计发现可疑”直接等价成“取消整个帧所有测量”。需要分别展示：

- 已验证的根部与可见中心线；
- 最后有证据支持的端点（不等于物理尖端）；
- 是否确认物理尖端及其坐标；
- 完整像素长度是否有效、为何有效或无效；
- 新搜索是否找到了真正的合理延续。

**验收必须同时量化**：误长尾减少多少、原来正确的长裂纹/弱裂纹被错误截短多少、漏确认/延迟是否增加，而不是只报“拦截了多少长尾”。

### 7.1 人工真值要求

优先在**原四组**建立人工标注（独立查看原图，避免叠加曲线诱导）：真实裂纹是否已出现、是否可见物理尖端、tip `(x,y)`、root、独立中心线折线/长度、明显遮挡与不可见状态、是否允许完整测量。由用户/领域人员复核，附标注口径和版本。

若人工 GT 未提供，Agent 只能创建工具与模板、输出代理统计，**必须承认无法计算真实尖端精度，也不能宣称算法提升了真实精度**。对分歧帧与随机帧同时采样，以避免仅关注已知错误。

### 7.2 指标和失败条件

必须输出开发集的：

- 有 GT 时：尖端欧氏误差 `MAE/P50/P95/P99/Max`、中心线定位偏差（明确距离口径）、完整弧长绝对/有符号误差、假确认、漏确认、首次可测帧确认延迟、`GT` 不可见时的误确认率；按试件和难度类别分组。
- 无 GT 时：确认/未确认数量及原因、路径弧长变化、共同有效帧尖端差 P50/P95/Max、候选长尾变化、每次有界重定位成功/失败/超时、人工复核样本；全部标为**代理/算法间差异，不是准确率**。
- 对比 v3 的“原四组净失去 336 帧确认”：必须统计新候选失去多少、新增多少、净变化多少，并逐类别复核是否为真实误拒绝。**不得仅以“比 v3 拒绝少”作为验收成功**。
- 合成 GT：必须包含无裂纹、真实短线、长裂纹、弯曲、多尺度宽度、短间隙、弱尾部、背景划痕、随机纹理、过曝细节丢失、遮挡/恢复、裂纹闭合、快速生长、已有裂纹参考帧和相位配准歧义。报告所有失败断言，不得只列通过案例。
- 安全性：`tip_valid` 与 `complete_length_valid` 的语义始终一致；无证据结果不继承历史；无效结果不得生成编造的非零物理长度；旧 C ABI、V2、ResetTemporal、baseline 查询、stride 和多实例隔离等通过回归。
- **出库限制**：若没有真实 GT，或若新模块带来无法解释的大规模确认损失、合成断言新增失败，不能声明高精度/高普适性，也不得成为默认生产配置；冻结最好稳定配置并报告未通过的原因。

### 7.3 如何选择最终候选

根据 **原四组 DEV-4（包括合成与已人工标注的 GT）**，综合选择 `false confirmed tip`、`missed true tip`、像素误差、长度误差、延迟和耗时之间的平衡。业务容差未知时请列出敏感性曲线/不同容差下统计，不要偷偷自行设定“3 px 即可发布”之类标准。**在冻结前完成全部代码、阈值、选择逻辑和失败分类。**

## 8. 性能与工程约束

- C++17 + 现有 OpenCV；默认 Release `/O2 /fp:precise`，保持当前 Windows x64 DLL 兼容及旧接口；任何添加的 V3/V4 结果字段须通过扩展/版本化方式实现。
- 内存中预载图像，**只计原生 Process**；逐组给出 P50/P95/P99/Max、最大新增耗时、异常分支最大耗时及 >66.67ms 帧数。新算法在目标测试机**全帧没有超过 66.67ms**为本轮速度门槛；建议 P99 不超过 60ms 留有余量。上述只是本次硬件/数据验收，不能称通用硬实时保证。
- 对长路径大量 ROI 验证需要优化：局部缓存、按需尺度、采样复用、跳过稳定强支持段、重定位次数有上限；避免每帧对整幅 5K 图像做 Hessian、多尺度或 ECC。
- 关闭全部新特征时，必须逐帧对齐冻结版原结果（排除允许波动的计时）；新开关每项单独消融，且没有未初始化状态或非确定性输出。
- 诊断图、完整证据数组、视频叠加与日志不得默认在生产热路径中执行。
