## 1. 绝对硬约束和研究伦理

**H1 冻结 A 原样不变。** 不修改 DP、`motion/refineRoot/tile/seed/ridge/process`、运动精修、历史状态、停止规则、生产 DLL 接口、已有参数及线上渲染合同。生产 A 必须可独立重放，所有状态/尖端/长度/双精度 CopyPath 与既有快照逐帧 0 差异。需要埋点时使用只读研究构建并做数值等价验证。

**H2 原始 Frangi F0 保留。** 解包代码作为不可变 F0 基线；移除副作用、修复路径引用或封装接口时，所有算法性差异必须单独登记在 F1。不得一边修 Frangi 参数一边宣称原 F0 已获改善；F0、F1 以及每个消融开关严格分离。

**H3 先公平对比，再选择融合。** 不允许见到排除组X 473 的视觉表现后立即加硬 ROI 限制到 A，不允许把 Frangi 热力图直接当真实尖端 GT，也不允许把 A 的路径当 Frangi GT。任何融合必须先通过独立测试、消融和回归门槛。

**H4 不要用户人工标注 GT。** 当前和未来项目都不要求手画中心线/标尖端。使用合成及半合成受控已知终点、无新生裂纹的受控负例、已知数字位移/旋转、参考历史的成对反事实、仪器加载相位（若有）。真实帧的尖端 MAE、召回/精确率、真实长度绝对误差均写 `N/A`，不把模型共识、长度趋势、CMOD 相关性或某个版本的端点当真实 GT。

**H5 视频严格。** 生产展示视频每帧只允许**原图 + 当帧该版本最终有效确认的一条连续中心线实线 + 1 个与该线终点一致的尖端点**；不确认只显示原图。左右两侧裂纹为**两个独立方向与测量对象**，不得偷合成一条“单裂纹”路径；如正式单路径合同不支持同时显示两侧，应按方向输出独立视频/结果，不改合同。绿色辅助线、虚线、候选、热图、搜索区域、差分、失证据点、文字标签仅放独立诊断目录。视频不能用旧内容冒充新结果，任何复用必须标明文件哈希、同一性依据。

**H6 实时性。** 对候选生产算法使用实际可集成的 C++17/OpenCV 4.4 路径，必须分开测试 `Process + 结果获取 + CopyPath + 必要分配`、预解码、图像输入适配、显示编码；核心 ≤66.67 ms/帧是硬门槛，提供每组 P50/P95/P99/Max、超时帧及峰值内存。Python 原型或平均 FPS 不代表 C++ 生产性能，不能靠未来 GPU 的推测宣称达标。

**H7 数据隔离。** 参数选择仅用预声明 DEV；固定后仅一次执行 TEST 对比和排除组X“已曝光留出复核”。不因 TEST/排除组X结果返回修改阈值；如修改则标记该样本为已开发并另建冻结测试。相邻帧相关，统计区间不得视为全部独立样本；使用试件分组/时间块和配对分析。

**H8 结果分类明确。** `IMPROVEMENT_PROVEN_ON_CONTROLLED_GT`、`GEOMETRY_ONLY`、`VISUAL_PREFERENCE_ONLY`、`NOT_IDENTIFIABLE`、`NO_IMPROVEMENT`、`REGRESSION`、`NOT_RUN` 与 `NOT_TESTED` 不得混用。准入以证据为准；允许失败并必须建议保留 A。

## 2. P0 —— 先定义可比较的“同一帧、同一坐标、同一测量目标”

### 2.1 建立统一的输入适配层（只读；不得改变冻结 A）

开发 `frame_manifest.csv`、`coordinate_contract.json`、`input_hashes.sha256`、`phase_manifest.csv`：

- 逐组列出参考帧、当前 `frame_id`、实际文件名、原图宽高、字节 SHA256、P1/P2 的来源与原图像素坐标、有效性、图像时间戳及可能的加载元数据；严格处理 `frame_id=0` 参考与变形帧的 0/1-based 索引；排除组X多余坐标行按旧已验证规则处理。
- 同一帧 A 和 F0/F1 使用**完全相同的原始图像字节**与**同一份 P1/P2**。不允许一个分支读取压缩视频帧，另一个读取原 BMP，除非先核对像素完全等价；不能一个算法偷偷使用自动点、另一个使用人工点，而称公平。
- 定义 `RAW_FRAME`（当前原图坐标）、`REF_FRAME`（参考原图）、`ROI_LOCAL`、`PHYSICAL_AXIS`（裂纹主延伸方向单位向量及法向）、`A_PATH_NATIVE` 和 `F_SKELETON_NATIVE`。列出正/逆变换的方向、矩阵、尺度、像素中心约定、裁剪偏移与插值方式。
- 对 Frangi 输出 `tip_roi`/`full_tip` 做严格审计：源代码中的 `ROI_X0+tip_x` 通常仍位于参考配准坐标，不可未经逆变换直接当当前原图像素尖端；建立 `tip_ref`、`tip_raw_current`、`tip_raw_reference` 三列，歧义时设 `COORDINATE_UNVERIFIED`，不许强行比较。
- 对 A 的最终端点与线各坐标重新核对 `GetResultV2`、`CopyPath` 和变换约定，不要把旧接口 0.01px 舍入误差当真实精度。已知相同点的 forward→inverse 数值测试、平移/旋转/镜像测试必须通过。
- 从 Frangi 原专用代码还原 `root`, ROI, MASK, `sigma`, `theta`, 形态学结构元与阈值到可读 `configuration_manifest.json`，避免“通用框架”偷偷带入每组专用常数。

### 2.2 加载相位：同帧配对与跨帧同相位是两种不同要求

- **同一原始帧上比较 A 与 F，天然处于同一加载瞬间**；这是本轮主公平对比，不依赖推测加载相位。
- **跨帧比较裂纹增长/时间稳定性**须优先使用真实同步的载荷/位移/触发时间戳，识别峰值开口、谷值闭合和周期。只有仪器数据可核验时才标 `PHASE_VERIFIED`。
- 如果仅有 `|P2-P1|` 差值，可将其称为 `GAUGE_DISTANCE_CHANGE_PROXY`，使用程序明示的近似相位分箱，并标 `PHASE_PROXY_ONLY`；**不等同于真实载荷/物理 CMOD**。
- 不得将 `frame_idx % 3` 或脚本里 `cmod > 0` 当已验证的加载相位；禁止以这种标签建立“同相位准确性”结论。
- 没有同步相位记录时，跨帧同相位对比记 `NOT_EVALUABLE_PHASE`；仍可完成同帧严格配对与受控合成相位实验。
- 所有相位分箱事先冻结边界，显示分母、同周期/跨周期、重复测量标准差；不能根据检测长度选择所谓“峰值帧”。

### 2.3 三套不同的长度量必须同时提供

对每条有有效中心线的路径/骨架，统一计算并标记：

1. 原图尖端二维坐标 `(x_tip_raw,y_tip_raw)`，原参考坐标 `(x_tip_ref,y_tip_ref)`；亚像素仅在实际具备浮点拟合时声明，整数骨架尖端写 `PIXEL_LEVEL`。
2. **主裂纹方向投影长度** `a_axis = dot(tip-root, unit_growth_axis)`，必要时同时报告水平投影 `a_x`，明确左侧的方向号。
3. **中心线弧长** `L_arc = sum ||P_{i+1}-P_i||`，依照相同原图像素坐标。Frangi 必须从骨架中选一条与根部真正连接的**单一有序主路径**才能计算弧长；不能把所有骨架像素数或最外侧 x 当弧长。
4. 双侧 CT/圆孔 M(T) 只在物理语义一致时统计 `a_left`、`a_right` 和 `a_total`；单侧 A 路径不应与 Frangi 左右长度和比较。没有对应方向输出时，单独标 `NOT_COMPARABLE_SIDE`。
5. 统一 `tip_valid`、`full_length_confirmed`、`candidate_only`、`no_detection` 和 `not_evaluable`；不能把未确认当 0 长度，也不能把根部位置当有效真实尖端。

开发 `unit_tests_coordinate_and_length.py` 或 C++ 等价测试，用已知直线、折线、弧线、左右向、边界裁剪、子像素位移验证三类长度及坐标回投，保存浮点前后值、容差与失败样本。

## 3. P0 —— 建立不可偏袒任何算法的独立已知端点测试

### 3.1 受控数据设计与可观察性边界

从前四组**空间分离且不可出现未知活跃裂纹的参考纹理区域**构造半合成样本（若材料静态性无法核实，明确 `CONTROL_BACKGROUND_ASSUMED`）；加完全程序合成背景以排除泄漏。DEV/TEST 不仅种子不同，背景来源裁剪区域、曲线形状模板及扰动条件也要分离。保存真实背景引用、合成参数和最终输入图像哈希。

每个案例提供参考帧、若干当前帧、P1/P2 原始坐标、严格已知的**注入中心线、根部、尖端、裂纹存在/不存在状态**。生成最终图像前后保存每次变换以保证 GT 坐标与实际像素一致，并验证注入线在经过 8-bit 量化后是否真实可观察。

必须覆盖以下正例：

- 直线/弯曲/S 形、远离水平 ±35° 的转向、边缘多叉但主干已知、左右双裂纹、不同根部结构（CT 缺口与圆孔）；
- 暗线宽度 0.5～多像素、强暗线、渐浅弱末端、半开裂/闭合、断续微间隙、轻微模糊、有限曝光/反射变化、边缘不规则；
- 已知真实尖端却灰度不可见或只部分可见的样例要明确区分 `GEOMETRIC_GT` 和 `IMAGE_VISIBLE_GT`；若信号已消失，算法不可能从图像恢复已消失的部分，不得将其直接解释为算法可修复误差；
- 根部偏差、运动平移/旋转、局部非刚性差异、真实可观察线逐帧生长及保持不变、相位开闭变化但**已形成物理裂纹长度不变**的案例。

必须覆盖以下负例与混淆对照：

- 无新增裂纹、参考与当前都有同一条静态根部暗线（必须设计有一部分能够诱发某种算法**完整确认**，否则不能测试纠错）；
- 参考已有划痕 + 当前轻微配准误差导致的单向差分双影；孔洞边缘张开/位移伪线、照度漂移、运动模糊、噪声；
- 根部附近有几乎贴合/交叉的静态线纹、近似平行分支，形态学桥接可能错误连通；
- 新增线并不连接实际裂纹根部、裂纹方向越过 35° 门控、路径真实出界、靠近 ROI 边界的可见线；
- 差分全零（参考自差分）只作数值自检，**不能**充当背景假阳性测试的全部分母。

对每项给出“本来该检测什么”的独立物理/程序条件；对于合成仅可证明该生成机制下的测试精度。覆盖至少多种几何、材料纹理及对比度水平；如实际样本数量不足，报告 `LOW_POWER`，禁止追求漂亮的百分比。

### 3.2 受控真实采集（有设备才执行）

如果能接入相机/光源/移动台/加载机，先在软件预注册实验后使用已知暗线端点靶、随材料运动的独立标记，至少三档真实曝光或光强及多次重复，记录 RAW/ADC 位数、增益、时间戳、载荷相位。标记由程序或测量设备给出，不要求用户人工标注疲劳裂纹。

没有硬件就交付**可执行采集协议**、所需 metadata schema 和 `NOT_RUN_HARDWARE`；严禁将 XOR1、gain/offset 等数字扰动冒充真实曝光或加载相位验证。

### 3.3 已知 GT 的主指标（所有算法及消融共用）

- `tip_error_px`：仅对定义一致、可观察且正确确认的样本，二维原图坐标欧氏误差；报告均值/中位数/P90/P95/Max、尾部 `>8px` 数，说明 8px 是工程预设判据而非真实项目容差。
- `axis_length_error_px` 与 `arc_length_error_px`：与相同定义的 GT 比较，给出**偏长、偏短两个方向**及相应偏差分布；弧线不能将投影与弧长混算。
- `centerline_distance`、已配准根部误差、主干提取正确率、连通域错误连接、截短或超尾比例；对无中心线输出单列。
- `FP_confirmed/negative_count`、背景尾部错误延伸数量、`FN_confirmed/positive_count` 和**覆盖率**；提供条件误差与总体拒绝率，不能通过把困难正样本全部拒绝来降低 MAE。
- 针对物理已形成长度不变但加载闭合的对照，区分 `visible_line_length` 与 `formed_crack_length`，报告同相位稳定性、跨相位缩短和假增长，不使用单调补齐当正确答案。
- 每个指标按组、难度、方向、根部类型、相位、运动扰动、参考差分质量、ROI 范围以及 GT 可观察等级分层；报告置信区间，使用材料/时间块聚类或按样本组聚合，避免把视频邻帧当独立观测。
- 全量逐样本 paired A-F-消融 CSV 包含 **所有失败、未确认和不能比较** 的原因，不可只报成功样本。

## 4. P1 —— 两算法的**真正公平对照**与差异拆解

### 4.1 先做“真实部署原生模式”对照，再做“控制变量模式”

**模式 NATIVE：** `A0 = 官方冻结 A`、`F0 = ZIP 原始 Frangi`，各自在其设计的运动补偿和 ROI/参数下运行；主分析同一原图/帧/P1/P2，最终结果统一回到同一 `RAW_FRAME`/相同方向量纲。这说明实际交付体系的总体差异，但**不能**将差异自动归因于 Frangi 过滤本身。

**模式 CONTROLLED：** 构建可读写中间结果的研究工具，使用共同的可验证参考/当前帧几何变换（由输入 P1/P2 + 已知合成运动，或者独立有效的运动真值）和**预先固定的物理主区 ROI**，隔离各模块贡献。A0 不允许被修改以接收新运动；对于 A0 无法以公共变换重放的部分，保留 NATIVE 比较，不能谎称完全共变换。可用 Frangi 的共同配准重放，以及 A 冻结研究镜像的只读/严格等价反事实来研究采样影响，必须区分生产 A 与研究反事实。

所有实验至少交付 `paired_inputs_manifest.csv` 和 `paired_outputs_raw_coordinates.csv`。明确相同帧是否同相位，以及原始工作 ROI 的覆盖交集、路径出界/不可比原因。**不得将 A 的宽搜索结果直接与被 Frangi 200px 窄 ROI 截断的路径比较，然后称 Frangi 更准确。**

### 4.2 模块消融矩阵（预先冻结；参数预算一致）

至少实现下述有明确名称和输出的研究版本：

| ID | 构成 | 要隔离的问题 |
|---|---|---|
| A0 | 完全冻结 DP | 官方基线 |
| F0 | ZIP 原始 Frangi（试件专用 ROI） | 现有交付总效果 |
| F1 | 统一坐标和路径输出语义的 Frangi 适配版，不改变检测逻辑 | 测量定义与代码移植影响 |
| D | 同一对齐输入上的单向参考差分 + 原有简单脊线/阈值，不使用 Frangi | 参考差分是否是主要收益来源 |
| D+G | D + 根部/缺口几何门控 | 物理空间约束的独立收益 |
| D+F | D + Frangi，但不使用形态学桥接 | 多尺度响应本身的增量 |
| D+F+G | 增加同一预声明几何门控 | Frangi 与几何门控的交互 |
| D+F+G+C | 再加入形态学桥接和连通域 | 桥接能修复弱中断还是产生假连通 |
| D+F+G+C+S | 再加入骨架及主路径端点选择 | `argmax x` 与根部连接的主路径端点差别 |
| F-WIDE | 在相同物理目标、预声明扩展 ROI 及负例下重跑同参数 Frangi | 窄 ROI 是否隐藏错误长尾 |
| F-NATIVE-ROI | 保留原硬编码窄 ROI | 与 F-WIDE 成对比较 |

此表是**实验分离设计**，不要求更改 A 的核心路径搜索；如某模块组合需要合理定义的简单基线，应声明算法细节，不能伪称仅切换 Frangi 而实际改变多个模块。两尺度、方向门控、阈值、结构元、根部距离全部进入参数清单。至少对 `theta=35°`、桥接尺寸、`sigma` 做冻结的受控弱线/弯曲/假连接敏感性测试；只在 DEV 选参，TEST 不回调。

### 4.3 重点消融的真实问题

1. **排除组X frame_id=473**：现有 A 输出 `(2344.05,2409.42)px`、路径弧长 `1084.13px`，有已知长尾风险。原 Frangi 排除组X ROI `x=550..2449, y=1980..2179`，A 尖端 y=2409.42 天然在该 ROI 之外。一定要独立比较 F-NATIVE-ROI / F-WIDE / 仅差分 / 差分+几何 / 完整 Frangi，精确量化“窄 ROI 截掉长尾”的贡献。不同坐标需正确逆变换后比较；这帧已知，不用于参数选择或宣称盲测。
2. **排除组X frame_id=51**：A 未正式确认，Frangi 曾报告左右短响应；要区分“新增真裂纹”与“孔边缘/静态差分残留”，证据不足时不得把 Frangi 的额外输出当正确检出。
3. **CT2 frame_id=6/18/84**：此前已证明 refine 运动映射会使 DP 同路径继续延伸的停止 tile 不同。研究 Frangi 在公共输入运动（已知 GT 时）和原生平移模式下的反应，区分几何差、前缀/延伸差、背景差分伪线。
4. **开发组H**：Frangi 左右总长度有过相邻帧千像素级缩短；按真实加载相位或明确代理逐组报告，不能直接把巨大瞬时缩短当检测错误或真实物理裂纹回缩。
5. **验证组C**：Frangi ZIP 没有本组专用脚本。要求使用在其他 DEV 上冻结的通用物理坐标适配，不允许针对验证组C重新手工画 ROI/调参数之后宣布成功。若不可移植，正式报告为 `GENERALIZATION_GAP`。
6. **所有组**：测试渐浅末端、弯曲越过方向门、闭运算假桥、孔/缺口边界重影、静态根部暗纹，并检查无确认时是否能正确保持原图。

### 4.4 稳定性而非仅“好看的视频”

输出相邻帧尖端跳动、长度增减、两侧对称性、同相位周期内重复性、连续性破坏及背景伪确认；对 A/F 的各类动态指标提供对应实际加载相位标签。**同一帧 A-F 比较与跨帧裂纹增长验证必须分列**。趋势相关 `R²`、左右相关系数或画面平滑只能作辅助，绝对不能替代物理 GT。

## 5. P1 —— “借鉴 / 融合”研究，只允许先做旁路与可消融候选

不要设计一次性大型混合新架构。根据第 4 节结果只从**具有独立收益**的模块挑选，按以下最小融合梯度运行：

| 候选 | 内容 | 禁止行为 |
|---|---|---|
| H0 | A0 原样，Frangi/差分/几何全部 shadow 观察 | 不改变正式确认与端点 |
| H1-G | 只把已独立证明有效、可泛化的试件几何 ROI/根部约束做**诊断或前置输入审计** | 不能凭缩窄 ROI 直接剪掉正确弯曲裂纹 |
| H2-D | 对 A 的**原有路径**进行可信参考变化与背景匹配的旁路评分 | 不能因参考配准不可评价而硬拒绝 A |
| H3-F | Frangi 在 A 路径上提供辅助线形证据（可选小 ROI/短剖面），保留 A 的搜索与路径选择 | 不可默认修改 DP 得分、跨空洞强桥、强行重接路径 |
| H4-Topology | 仅在合成已证明的错支/假连接子类中，用根部连接一致性提出风险标记或可撤销的局部测量建议 | 不得将影像证据失效点直接称真实尖端；不许大量撤销确认换取较低 MAE |

**顺序强制：** H0 影子证据 → 单机制 H1/H2/H3/H4 独立消融 → 如果至少两项确实互补，再试联合作用。不得因融合候选“看着合理”就把 Frangi 以权重加入 A `tile()/ridge()` 评分；如最终研究不得不修改 DP，必须另建实验分支、不可变 A baseline，并与 H0 做独立、可回退的对照，不能混入本轮默认交付。

融合收益必须同时满足：

- 在预注册的程序 GT **可观察**测试上，较 A0 或相应单模块的配对尖端误差、方向长度误差、假长尾或误接受指标有实质改善，且不是单纯减少确认数量；
- **弱线、渐浅、非水平弯曲、双侧、孔边缘、静态纹理**等重点子类没有不可接受退化；报告每个子类被错拒绝/误截的精确案例；
- 与 F0、F-WIDE 和最简单差分+几何基线同时对照，证明 Frangi 相对简单模块确有增量，而不只是在改 ROI；
- 在四组既有数据中原 A 确认覆盖率 1786/1987 作为**保覆盖参考，不是真值下限或必须原封不动的绝对要求**；任何减少确认须逐帧给出独立证据，不得直接按“减少误报”归功；
- 全部原有 A 数值回放 0 差异，所有候选单独 DLL/EXE 或 shadow 配置，不破坏旧 API；
- 实测 C++ 原生全帧 Max ≤66.67 ms；如果不能满足，判 `RESEARCH_ONLY_PERFORMANCE_FAIL`。

**预设准入/拒绝策略：** 在研究正式开始前用程序 GT 的 DEV 确定可量化门槛（例如相同误接受约束下配对误差至少有 10% 降低、弱线漏检不得显著增加、尾部错误不得扩散、通过覆盖不靠全拒绝），将绝对阈值和统计方式写入 `preregistered_metrics.json` 并冻结。最终 TEST 严格按此执行，若不满足就是 `NO_IMPROVEMENT`。不得使用排除组X 51/473 来挑选门槛。
