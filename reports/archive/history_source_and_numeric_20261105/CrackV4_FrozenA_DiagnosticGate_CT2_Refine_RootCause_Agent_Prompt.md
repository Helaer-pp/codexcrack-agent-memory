本任务最终需要回答五个决定性问题：

1. **光度门控失败是真正的信息丢失，还是诊断指标设计不当？** 为什么除验证组C外四组基础光度均为 0 可用？

## 4. Phase 1 — 光度诊断规则是否有效（不是算法优化）

### 4.1 重新拆解图像信息，而不是调低 15% 阈值

分别在**材料背景、路径中央、路径两侧、基准点邻域**统计：

- 直方图：`[0..15]`、`[16..239]`、`[240..249]`、`[250..254]`、`255`，尤其区分高亮与真正编码上限堆积；记录 8-bit 解码链和可能的灰度映射。若没有 RAW/传感器元数据，饱和源头写 UNKNOWN。
- 局部动态范围：P1/P99、局部对比度、不同区域背景起伏、局部高频 MAD（明确包含纹理而非纯噪声）。
- 路径的横截面暗谷强度与相邻背景的对比/噪声比；沿路径分段统计（根部/中部/末端），不能只报告全图亮度。
- 配准风险：参考与当前帧中**已知无新增变化**且空间上远离裂纹的背景区域亮度差分分布，按局部高亮占比和材料类型分层。不得把所有变暗差分当新裂纹。
- 控制变量：对同一原始图施加**可逆、已知且不改变几何**的数字亮度/对比度扰动，检查当前门控、局部暗谷信息与冻结 A 输出稳定性；数字扰动不等于传感器重新曝光，必须单独标注。

### 4.2 证明/证伪当前光度门控

设计下面三种互斥结果解释：

- **CASE-P1：亮背景但裂纹局部证据仍保留**：全图高灰度门控为 fail，但暗谷相对背景仍显著、对照扰动下稳定。将原门控标记为 `OVERCONSERVATIVE_FOR_CURRENT_LINE`，但不可推断参考差分安全。
- **CASE-P2：局部确有不可恢复的编码损失**：关键局部区域大量像素达编码上限且细节/对比不可区分；若没有原 RAW/曝光元数据，最多断言“8-bit 表示中信息不足”，不要断言相机 ADC 饱和。
- **CASE-P3：证据不足**：纹理、反光、加载变化使信号解释不唯一，标记 `INSUFFICIENT_EVIDENCE`。

光度诊断改进仅输出新的**只读质量标签**，不能更改冻结 A 是否确认。

**重点**：开发组A“高灰度占比 57.98%，却有 494/550 当前线形支持至尾端”必须给出逐帧对照与统计，说明全局亮度门控和局部线可辨识不是同一个指标。开发组H `96.19%` 高亮背景也必须分开分析编码裁剪、局部纹理和真实可辨识性。

## 5. Phase 2 — 独立局部材料匹配：失败原因分层，不靠放宽阈值刷成功率

### 5.1 保留上轮基准条件

首先严格复现 `31×31` 模板、`±12 px` 搜索、16 个基准点邻域材料样本与候选两侧 8 个样本、训练-验证空间隔离，以及上一轮实际 NCC 门槛。**必须先得到可比较的 3/12808、3390/13344、0/11208、0/9448、3393/12288 或解释差异**。

随后把所有匹配尝试写成 `match_attempts.csv`，每次记录：group/frame/patch ID、ROI 来源和原图坐标、是否含孔边/裂纹、局部方差、梯度能量、有效灰度范围、搜索矩阵尺寸、预测位移、最优/次优 NCC 分数及间距、最佳位置是否在边缘、前后向位移一致性、纹理唯一性、实际拒绝规则及顺序、验证点残差。

### 5.2 失败类型必须互斥、可复核

为每次尝试给出**首个失败原因**和可多标签的次要原因。最低包含：

`OUT_OF_BOUNDS`、`LOW_TEXTURE`、`CLIPPED_OR_LOW_DYNAMIC_RANGE`、`PHOTO_INCONSISTENT`、`SEARCH_EDGE_OR_RANGE`、`AMBIGUOUS_PEAK`、`NCC_BELOW_THRESHOLD`、`FB_INCONSISTENT`、`GEOMETRIC_CONFLICT`、`HOLDOUT_VALIDATION_FAILED`、`VALID_MATCH`、`OTHER`。

以上分类门槛应由**原四组与已知几何变换 DEV**设计，并输出定义；测试阶段不得按排除组X反例返调。明确哪些类别只是**可能原因**，哪些有可控实验支持。

### 5.3 已知运动的算法能力检查（必须）

基于原四组真实背景抽取不同纹理强度的 ROI，施加已知的：

- 亚像素平移、整数平移、小角度旋转，包含落在搜索边界内外的条件；
- 亮度偏移、对比度缩放、局部照明梯度、噪声扰动；
- 低纹理与重复纹理区域；
- 可区分的含已知局部非刚性位移的合成测试，但不可暗示上轮材料实际发生相同形变。

计算已知变换恢复误差（median/P95/max、>0.5 px 数量）、接受率、错误接受率及原因分布；**在相同可评价分母上**比较是否相较既有匹配诊断更可靠。

NCC 0.60/0.75/0.90 的比较必须同时报告错误接受，不得只看成功数。可以离线对比“窗口由 ±12 扩展”的效果，但这仅验证搜索边界假说，不能直接上线替换配准实现；若增加窗口导致候选歧义或错误上升，必须如实说明。

## 6. Phase 3 — CT2 `refine` 配置差异源码级根因定位（最关键）

> **主要目标：回答 P95 127.21 px 的尖端分歧从哪一步开始产生，以及通过什么因果链传播。不是决定哪个配置“更准确”。**

### 6.1 先审计 `refine` 的真实作用链

从冻结源码开始，优先检查旧实现中可能涉及的函数（以当前实际工程为准）：

- `Detector::motion(...)`：P1/P2 初始化变换；在 `cfg.refine && !isref` 时是否运行参考背景 patch 的 `cv::phaseCorrelate`；有效 patch 数、响应、位移、离群剔除。
- 运动精修的分支：有足够支持 patch 时是否采用刚体旋转/平移拟合；否则是否仅增加平移修正；失败时怎样回退。尤其记录 `refined` 的实际布尔结果、rotation/translation 的变化量。
- `Detector::seed(...)`、`Detector::refineRoot(...)`：实际根部和初始搜索位置有没有变化。
- `Detector::tile(...)` 和坐标映射/插值：两配置是否在不同的**图像位置取样**；当前帧/参考帧响应差异来自哪里。
- `ridge(...)` / 路径 DP / `Detector::process(...)`：累计得分、回溯前驱、最终路径和确认是否改变。
- 接口转换：确认坐标和长度差异不是由显示裁剪、输出坐标转换或旧接口 0.01 px 舍入造成。

**注意：以上是调查入口，而不是允许直接修改的函数列表。实际函数名、调用顺序和源码分支必须用文件路径与行号确认。**

### 6.2 必须建立五级隔离对照

在保持冻结输出可复现的基础上，分别记录：

**L0 输入层**：同一 frame_id/原图 SHA、P1/P2、参考图、方向、ratio、ROI、flags、历史输入是否完全一致；两套独立初始化实例是否具有同等历史条件。  
**L1 几何层**：变换矩阵、旋转角度、平移、参考 patch 匹配数、响应值、精修成功或回退状态、参考坐标到当前像素坐标的映射差异场。  
**L2 采样/特征层**：根部起点、seed、有效 mask、实际 tile 位置、背景处理、归一化响应、沿线采样灰度和 DP 输入矩阵差异。  
**L3 DP 决策层**：候选得分、前驱状态、最优/次优路径边际、路径累计评分、首次几何分歧位置、局部备选竞争位置；**只记录既有 DP 的选择，不添加多候选跟踪逻辑**。  
**L4 输出层**：两端尖端、弧长、确认、路径点数、路径 Hausdorff/平均距离等**版本间分歧指标**，并注明非真实误差。

不能只输出 CT2 两个版本的最终尖端差值。至少对首个分歧出现处、早期几帧、差异最大的帧，以及分歧在时间上首次扩大时的邻近帧进行逐步溯源。

### 6.3 首次分歧定位算法

- 两条路径必须首先统一到**同一原图像素或等价材料坐标系**，避免不同采样坐标误算为路径分支变化。
- 依次检查根部/初始点偏差、路径公共前缀长度、首次持续分歧弧长及两条路径是否重新汇合。
- 首次持续分歧条件由前四组与合成 DEV 预设，记录不同容差（例如 1/3/5 px）的灵敏度，不要只汇总单个阈值结果。
- 对 `refine=true` 和 `false` 路径的分歧做三类归因：`COORDINATE_SHIFT`（路径拓扑相同，仅整体几何移位）、`BRANCH_SWITCH`（相同根部附近选择不同线状支路）、`SEED_OR_ROI_CHANGE`（上游已不同）；不能区分标记 `INDETERMINATE`。
- 在原四组上挑选**同输入、只差运动变换**的受控因果反事实实验：将两种 motion 结果记录到同一个只读 replay/trace harness 中，控制后续输入差别，用于判断差异主要由几何采样还是 DP 决策放大。若技术上无法保持一致，不得宣称完成因果隔离。
- DP 最优解的分数差距如果很小而路径差异很大，应报告潜在**近似平局 / 最优解敏感性**；不能凭少量边际就假设找到了物理正确分支。

### 6.4 无需所有 467 帧都输出巨型调试矩阵

**全量逐帧**保留 compact trace CSV/JSON：运动矩阵、patch 数、refined 标志、根部/seed、确认状态、尖端差、长度差、首次分歧位置、初步归因、耗时。

**深度 trace**仅按前四组 DEV 预先规定的规则选取：

- CT2 最早产生显著分歧的若干帧；
- CT2 差值 P95 附近/最大值及前后连续帧；
- CT2 近似无差异的负对照帧；
- CT2 精修 patch 被拒或匹配数边界的典型帧；
- 如存在，来自其他前三组类似分歧的对照帧。

全量输出用于统计，深度 trace 用于解释。深度 trace 不可偷偷改变正式路径，也不得产生影响实时性测试的日志开销。

**交付**：`03_CT2_refine_root_cause.md`（逐函数、逐分支、逐证据链）、`ct2_refine_trace_all.csv`、`ct2_root_cause_cases.csv`、`ct2_path_first_divergence.csv`、关键案例图、研究版源码差异与仪表化日志。

### 6.5 CT2 根因验收

完成本模块必须满足：

1. 双配置的相同输入与独立历史得到保证；
2. 重现 `P95≈127.21 px` 和 `Max≈133.90 px` 的原对照（允许解释统计口径导致的微小差别）；
3. 对至少主要分歧类别给出“**第一个不同的内部量 → 如何影响后续 → 最终分歧**”的可复现链路；
4. 全部无法解释的帧列 `UNEXPLAINED`，不以粗略相关性冒充因果；
5. 不凭配置分歧宣称 refine 开/关谁更准确，也不把真实尖端误差称为 127 px。

## 11. 验收逻辑：不要求这次检测精度提高，但要求根因可解释

下面是最终接受专项诊断报告的标准。**不允许因为困难样本被全部拒绝而宣称成功。**

### 11.1 必须通过的工程性要求

- [ ] 冻结 A 生产源/DLL/ABI/算法参数未变，SHA 复核及 2510 当前帧一致性为零差异；如果缺数据，不能伪报全量通过。
- [ ] 两种 refine 配置由独立状态回放，输入固定且差异来源有逐层日志；给出 CT2 首次分歧及关键函数证据。
- [ ] 光度门控报告分离“亮度上限风险”“当前线形对比度”“参考差分可靠性”，并给出开发组A等反例。

- [ ] 每个组别最终独立报告成像可辨识性、配准可验证性、路径主体可观察证据，缺项用 N/A 或 UNKNOWN，不伪造误差。

- [ ] 不以 coverage、版本分歧、NCC 成功率、代理线形支持或合成结果冒充真实尖端精度。

### 11.2 根因判定分级

对每个问题使用统一证据等级：

- `CONFIRMED_CAUSAL`：有可控实验或源码输入隔离，证明原因改变导致特定中间量及输出改变；
- `SUPPORTED_ASSOCIATION`：存在重复统计关联和合理机制，但尚缺对照；
- `RULE_LIMITATION`：诊断规则本身缺少适用范围/覆盖；
- `NOT_IDENTIFIABLE`：当前图像无法支持唯一解释；
- `NOT_TESTED`：输入或设备缺失；
- `REFUTED`：受控实验未观察到该机制，且写明检验范围。

**特别要求**：不能仅从排除组X `BODY_EVIDENCE_LOSS` 推断 “DP 跑错”，必须把“不足以判定”保留下来。

### 11.3 最终技术路线决策（最多推荐一项最优先工程动作）

写出明确的 go/no-go：

- **DIAGNOSTIC_REPAIR_FIRST**：主要是诊断门控不可观测或有效匹配不足，需要优先修验证方法而非检测算法；
- **ACQUISITION_EXPERIMENT_REQUIRED**：有证据显示采集动态范围/重复性是关键阻碍，但必须用实际硬件实验确认；
- **REGISTRATION_CAUSAL_ISSUE**：已用受控数据定位运动/变换传递链的具体问题，才进入局部或全局配准研究；
- **DP_BRANCH_SENSITIVITY_RESEARCH**：CT2 确认由轻微采样/得分差异放大为路径分支跳转，可单独设计 DP 稳定性研发，不在本轮动冻结 A；
- **INFORMATION_LIMITED / INCONCLUSIVE**：无法在现有图像与无真值条件下归因，清楚描述缺少哪一种**可获得的受控证据**，而不是要求大量人工裂纹标注。

若不同组需要不同动作，先写分组建议，再基于证据强度推荐一个总体最优先动作。不要以“功能更多”“通过率更高”作为出库依据。

## 13. 最终向用户汇报的固定格式

请按以下顺序给出真实结论，不要写“算法效果显著改善”这类未被验证的语言：
