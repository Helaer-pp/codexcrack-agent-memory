# CrackV4：冻结稳定版 DP 的无真值尖端精度改进与五组回归实验

> **交给代码 Agent 的可执行任务书 / Prompt**  
> 研究方向：**不增加 Frangi、Hessian、二维多候选图搜索或新型 DP 停止状态**；基于已验证最稳定的 CrackV4 冻结版本，单独实验「测量链路审计」「时间生长证据」「沿既有路径的一维尖端精定位」。  
> 实验数据：**前四组用于开发、调参、消融和回归；第五组排除组X只用于源码/参数/评测方案全部冻结后的一次验证。**  
> 实时目标：**算法核心每帧 ≤ 66.67 ms（至少 15 Hz）**，不含读图、解码、可视化与视频编码。  
> 真实数据：**所有项目均无人工裂纹尖端、中心线和长度真值，未来项目也不得依赖人工真值作为运行前提或验收材料。**

## 0. Agent 身份与最终工作目标

你是负责 C++17 / OpenCV 4.4 工业视觉算法、数值测量、工程回归及实验可复现性的研发 Agent。请**亲自检查工程源码、构建、运行四组完整数据、生成消融结果和视频、冻结配置后运行第五组、提交完整可复核报告**。不要只给出算法建议或伪代码。

核心业务需求是：输入参考帧、当前帧及每帧真实 P1/P2（在可用时），跟踪从已知根部产生的疲劳裂纹，输出**当前帧真实可观察的裂纹中心线、尖端像素坐标及中心线弧长（px）**。无足够图像证据时不得把虚假延伸伪装成有效测量。

本轮采用**小改动、强对照、可证伪**策略：

1. **A：冻结稳定版**保持原始结果，作为唯一正式基线。不可为了让研究算法看起来更好而改写 A。
2. **A+M：只做测量链路审计及可验证的数值修正**，不修改路径搜索。
3. **A+T：只使用现有路径上的时间生长证据**，不修改路径几何或增加二维搜索。
4. **A+E：只在现有路径上做一维尖端估计**，不修改 DP 原候选生成与搜索。
5. **A+TE：融合时间证据和一维尖端估计**；M 中确证的数值错误应单独标记并在各分支统一处理或单独报告，避免混淆消融。
6. 可选择「实验结果不优于 A，不启用任何新模块」作为**合格且诚实的结论**。严禁为了得到“改善”而临时改变验收口径。

**禁止事项**：引入机器学习/深度学习，增加 Frangi/Hessian/Gabor 等滤波器作为新检测层，增加二维末端重搜索或多分支路径搜索，改写冻结版 DP 的 seed/tile/ridge/得分/历史核心决策，针对第五组调阈值，凭空造出 GT 或报告真实图像 MAE/P95 精度数值。

## 2. 研究原则：先测定失败归属，绝不直接改 DP

对明显错误长尾、疑似过早终止、路径从中途偏离、配准异常、曝光饱和、无裂纹时假确认、弱裂纹无法确认等问题，区分：

| 类型 | 解释 | 本轮可否修复 |
|---|---|---|
| G：几何/坐标/长度计算失误 | 正确路径在坐标还原、插值或弧长计算中产生误差 | M 可尝试；须有数学不变量证明 |
| E：路径主体正确、末端外推或过早停止 | 大部分中心线在真实裂纹上，末段不正确 | E/T 有机会修正 |
| B：DP 中途选错分支或根部 | 真实裂纹已不在固定路径上 | **本轮不能保证恢复**；只能标记异常，不可声称已校正 |
| Q：图像不可测（模糊、饱和、闭合等） | 现有成像缺失必要证据 | 不得虚构尖端；需报告观测局限 |
| R：参考帧/配准不可信 | 时间差异的坐标或亮度依据错误 | M/T 必须屏蔽不可信更新 |

**验收重点**是可靠区分 E 与 B：如果 DP 中途已跑偏，禁止一维算法强行在错误路径上找到所谓“正确尖端”。对明显不适用的帧，新测量可退回 A 或报告不确定，但**不得静默展示历史尖端为本帧识别结果**。

## 3. A+M：测量链路审计，优先修复可确证的系统性误差

这项实验不涉及任何新裂纹检测器。至少核对：

1. 原图坐标、算法局部 ROI 坐标、参考坐标、视频裁剪坐标之间的正逆变换、像素中心约定、整数/浮点舍入、OpenCV 采样约定。
2. 每帧 P1/P2 顺序、从外部 anchors 到算法变换的方向及逆变换一致性；参考点残差不是尖端误差。特定工况方向仅可作有记录配置，不应默认为新项目恒成立。
3. 旋转、缩放、亚像素平移下固定路径的坐标可逆性；数值变换后的误差可用**程序生成已知坐标**测试。
4. 路径重采样、平滑、折线弧长：`L = sum(hypot(dx,dy))` 的定义是否始终在**原图像素坐标**计算；不允许图像显示裁剪、视频缩放影响弧长。
5. 确认有效位与路径数据之间是否一致：无效帧不可仍宣称完整长度有效；路径点端点是否对应返回的尖端坐标；任何插值或平滑不得偷偷移动真实端点。
6. 本帧曝光大幅变化/饱和/遮挡时，应记录“不可测/配准可疑”诊断，不能假设可通过图像增强恢复已丢失的物理信息。

**M 的交付**：`measurement_chain_audit.md`（每项证据及代码位置）、构造测试程序和可复现的亚像素几何测试。仅修正确凿的坐标/弧长软件错误；不能以改变裂纹曲线形状或调阈值的方式“修正数值”。如查无错误，M 应报告 **NO_CHANGE**。

## 4. A+T：沿既有路径的轻量时间生长证据（不追溯修改 DP）

### 4.1 工作范围

- 仅沿 **A 已输出的本帧路径**及很窄的固定法向带采样参考图、当前图和限定数量的历史帧，不进行二维候选分支搜索。
- 当前图与参考图先在**可验证的材料坐标**下进行亮度/几何对齐。若相应帧配准、曝光或局部一致性无效，T 必须退化为“不可评价”，不能把差分当作新生裂纹证据。
- 计算固定路径上各段的「静态已有线纹」「新增变暗」「背景变化」「持续时间/复现」等**可解释诊断量**；避免因为强背景线状响应将静态纹理视为新裂纹。
- **参考图不保证完全无裂纹**。参考帧本来已有的可靠裂纹前缀、尚未成像的新裂纹和静态划痕，应分开解释，不能一律要求整条已知裂纹每帧相对参考都新增变暗。
- 当只有当前帧、缺失历史或帧时间不连续时，T 必须安全退化至 A；历史数据缓存有限，不能为每帧遍历全部过去图像。

### 4.2 不可违反的物理和统计约束

- **“同一帧可见裂纹长度”不等于“材料历史最大裂纹长度”**。裂纹受加载相位和闭合影响，不能强制 `L_t >= L_(t-1)`，不能直接拿历史最长尖端充当本帧输出。
- 时序稳定也不意味着真实：材料上的划痕可能连续几百帧保持稳定。时序证据应与“参考差异/近期新增”分开记录。
- 配准和曝光需要质量门控，但不能把全图平均亮度变化、孔边界变化、材料整体变形误判为裂纹生长。
- T 作为**观测证据**，不允许把「与时间先验不一致」直接设成整帧永久无效；需要记录 A 原输出与 T 建议及证据冲突。
- 不使用第五组的任何图像、统计、误差截图来拟合或选择时间窗口、阈值。

### 4.3 最少输出

每帧至少：`temporal_evaluable`、`reference_registration_quality`、`brightness_quality`、`new_growth_evidence`、`static_texture_evidence`、`temporal_support`、`temporal_reason`、`baseline_tip`、`temporal_suggested_tip`（如存在）。所有分数必须说明定义与量纲，不能冒充真实概率。

## 5. A+E：仅沿原路径的一维末端定位

### 5.1 绝对边界

**保留 DP 完整输出路径 `P(s)` 不变**（通过只读副本或 sidecar postprocessor 实现）；不允许增添任何二维重搜索、路径分支替换或改变原有起点/中段几何。E 只能选择原路径上的停止弧长 `s_end` 或输出不确定；亚像素插值只在该路径邻域进行，并必须记录其来源。

### 5.2 可实现的无学习测量步骤

1. 计算原路径累计弧长 `s`，并在固定弧长间隔上进行插值；路径长度短或点数少时安全退出。
2. 沿切线定义法向 `n(s)`，用 `cv::remap` / 双线性采样等方式读取当前图中**中心线及左右固定法向距离**的灰度或已有平滑图；参考图同样采样并记录配准有效性。
3. 构造可解释的横截面暗谷对比量，例如 `C(s) = (I(P+d*n)+I(P-d*n))/2 - I(P)`；需考虑裂纹宽度、孔边界、图像边缘、过曝、局部亮度梯度，并使用**前四组自动估计或固定的物理宽度/像素尺度规则**，不能针对第五组单独定制。
4. 记录沿路径的 `contrast(s)`、`reference_change(s)`、`local_background(s)`、`support(s)`、`quality(s)`；每项与目标的关系必须可视化为独立诊断曲线。
5. 只允许在**原路径尾部有界的一维区段**提出终点修正；如发现首次持续证据消失位置远离尾端，不直接将其宣布为物理尖端，而应判定为“路径主体可能错误”或退回 A。
6. 可尝试鲁棒分段或一维变点统计，但**变点 ≠ 物理尖端**；须增加端点附近有限区段的支持验证，以处理裂纹渐隐、局部闭合和短间隙。
7. 如果证据不足或分数冲突，E 应报告 `tip_uncertain`；正式启用策略前必须评估其对有效覆盖率的影响，不得把大量原本确认的路径静默抹除。
8. 输出新 `s_end` 后，中心线为**原路径的前缀**（包含弧长内插末端），长度在原图像素坐标计算；`tip` 必须与前缀最后一点严格一致。

**特别声明**：修正 `s_end` 可能减少明显长尾，但如路径中途跳到错误分支，E 没有能力恢复正确真实曲线。该局限必须在报告中逐案例明确披露。

### 5.3 E 的决策策略必须可回退

优先实验 `shadow_mode`：旁路产出 `tip_E / length_E / confidence_evidence`，**不覆盖** A 的正式结果。只有在四组消融与冻结验收表明有独立收益后，才在独立研究模式下允许输出 E 结果；稳定版默认仍为 A。任何启用条件与失败回退都必须可记录、可切换和可复现。

## 6. A+TE：轻量证据融合（不能变成新检测系统）

仅在 A 的既有路径上，将 T 的新增生长时间证据与 E 的一维末端支持作为两个独立观测来源进行融合；每个输出都记录两者是否一致、哪里冲突、是否回退 A。禁止：

- 先用 T 给出一个大致尖端，再围绕该尖端进行新的二维 DP 搜索；
- 因 T/E 不同就增设更多线状滤波器；
- 将历次最大长度或旧尖端“锁住”作为本帧尖端；
- 将没有根据的融合分数命名为 `accuracy`、`true_probability`；
- 在第五组复测后继续修改 TE 并将复测称作独立验证。

若 T 与 E 不能互补，**允许 A+TE 不超过其中最佳单项，甚至不如 A**。必须诚实报告，不能遮蔽失败。

## 7. 无人工真值下的实验设计与可证伪验收

### 7.1 数据隔离

**前四组——开发集**：开发组A、验证组C、CT2、开发组H MT 全序列均可用于机制分析、算法研发、消融、参数选择、程序化合成实验及回归；建议组间留一交叉验证，检查参数是否被某个材料过度适配。任何跨组共享参数必须记录选取过程。

**第五组排除组X——最终留出验证集**：只允许在下述文件锁定之后读取及运行**一次固定的完整序列评测**：算法源码 SHA256、参数 JSON、编译产物 SHA256、消融方案、统计脚本、视频规范、验收阈值。归档 `freeze_manifest.json`。排除组X frame_id=51、473 是**此前已知历史失败案例**，可以在冻结后专项复核，但不可声称它们是从未见过的盲测，也不可再据其结果返调参数并保持“独立验证”称谓。

### 7.2 真值口径

- **真实图像**：不提供人工标注 GT；真实尖端 MAE/P95、真实中心线误差、真实完整长度误差、真实检测准确率、召回率均填 **N/A**。外部双 anchors 仅用于几何检查，不代表真实裂纹尖端 GT。
- **程序合成图像**：在真实参考背景上注入已知曲线/尖端/宽度/对比度与真实图像变形/模糊/噪声，使 GT 由程序确定；允许计算合成尖端误差和弧长误差，但报告名称必须包含 `synthetic`，不可宣传为真实样本精度。
- **负对照**：同一帧与自身配准比较、未注入新增裂纹的真实背景、静态暗纹等，测试错误新增生长判断。参考帧可能已存在裂纹，因此只能将其作为“无**新增**生长”对照，不能未经证明就当作“完全无裂纹”GT。
- **变形一致性**：对图像施加受控可逆几何变换和亮度/噪声微扰，输出变换回原坐标系后比较坐标、弧长与确认状态；这是稳定性证据而非真实精度。
- **独立性测试**：同一帧冷启动/连续运行、不同合理历史长度、不同近邻参考选择下的结果稳定性，不得用时间平滑掩饰错误尖端。

### 7.3 必须测试的合成与半合成情形

最低覆盖：直裂纹、曲裂纹、逐渐变细、逐渐变浅、局部闭合/短间隙、真实裂纹末端后存在静态长暗纹、孔边黑边/环形纹理、划痕、颗粒噪声、轻微曝光变化、严重饱和、亚像素平移/旋转、局部配准失真、早期无新增裂纹、真实裂纹已在参考图存在一段、新增裂纹极弱、历史假路径污染、初始 DP 中途走错分支。

合成样本**不能只用干净空白背景**。必须保留真实四组的局部表面纹理和可能的假线结构；合成失败场景必须原样保存，不可挑选有利例子。

### 7.4 必须逐组对比的指标

| 指标 | 正确解释 |
|---|---|
| confirmed 帧数 / 覆盖率 | 代表可用输出比例，不代表真实精度 |
| A → 新版新增/撤销确认帧数 | 体现新策略代价，须分别列出，不允许只报净数 |
| 两版均确认时 tip 偏移 P50/P95/Max | 表示版本分歧，不代表尖端误差 |
| 两版弧长变化 P50/P95/Max | 表示版本分歧，不代表真实长度改进 |
| 冻结 A 路径被 E 截断的数量/距离 | 可解释变化来源 |
| T 能评价/不能评价的帧数及原因 | 防止时序条件不可用时暗中启用 |
| 暴露于错误长尾的负对照误确认率 | 仅在负对照定义内有效 |
| 合成 tip/length 误差分布与漏检/伪检 | 可提供有已知 GT 的受控精度证据 |
| 亮度/几何/历史微扰后的结果一致性 | 稳定性，不是正确率 |
| 每组核心时间 P50/P95/P99/Max，超 66.67 ms 帧数 | 真正验证 15 Hz |
| 每个新增模块的独立耗时/内存增量 | 判断收益是否值得成本 |

**禁止**用“新方案与 A 一样多的 confirmed”证明精度相同，也禁止用“撤销更多疑难帧”宣称精度更高。若出现显著覆盖下降，必须列出全部受影响帧和原因，不能只交最终合计。

### 7.5 预先固定的发布决策逻辑

## 10. C++ 工程约束与性能

- C++17、OpenCV 4.4，默认无 ML/DL、无额外大型依赖。维持既有 API/ABI 及旧 flags；A 的 `Create` / `CreateExtended` / `Process` 行为必须逐帧回归一致。
- 新模块作为**可关闭旁路或独立 DLL/实验扩展**。研究模式可新增接口但不得破坏已有客户端；任何 API 扩展必须配套版本号与兼容测试。
- 所有新计算限定在已有路径的有限带状采样、有限历史缓存和局部一次性数值处理中；禁止每帧重复全图处理或遍历全部历史帧。
- 性能报告须记录计算机型号、CPU、OpenCV 线程数、构建配置、Release 优化选项、每帧算法核心耗时；原始 I/O、预解码、画图/视频编码需分别统计并明确排除。
- 每个组给出 P50/P95/P99/Max、超 66.67 ms 帧数、最慢帧 ID 和模块时间拆解；如在目标平台没有真实运行，必须写 **NOT_TESTED**，禁止仅凭估算宣布 15 Hz 通过。
- 优先复用 A 已有结果缓存；消融必须使用相同输入、相同 frame_id、相同 anchors、相同线程环境。完整记录 A 不变性的逐帧比较结果及二进制哈希。
- 必须通过 AddressSanitizer 或相应内存检测（可用时）、空路径、极短路径、图像边界、坐标 NaN、anchors 异常、帧跳号、参考帧缺失、曝光突变等安全测试。
